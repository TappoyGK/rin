# Rin 言語仕様

## 1. はじめに

Rin は、ホストプログラムに組み込んで安全に実行できる、小さな純粋関数型 Lisp 系言語である。Rin のプログラムは評価器（インタプリタ）上で実行され、ホストから明示的に渡された値のみを入力として受け取り、計算結果の値を返す。

### 1.1 範囲

Rin は次のものを含む。

- 値と型：`i64`、`f64`、`bool`、`char`、`string`、`list`、`array`、`tuple`、`struct`、`variant`、`option`、`result`、`fn`、`void`
- 構文：`def`、`defn`、`fn`、`let`、`if`、`when`、`match`、`with`、構造体リテラル、バリアントリテラル、リストリテラル、タプルリテラル、フィールド参照、添字アクセス、関数呼び出し
- 組み込み関数：算術・比較・論理・型変換・数学・リスト高階関数

Rin は次のものを含まない。

- 変数の再代入（`set!` 等）および可変なデータ構造
- ファイル I/O、ネットワーク、時刻、環境変数、標準出力、乱数などの暗黙の権限
- ホスト側関数へのコールバック（副作用は、操作を表す値を戻り値としてホストへ返すことで表現する）

### 1.2 安全性と不変性

**[value.immutable]** Rin のすべての値は不変である。束縛された名前への再代入はなく、構造体の部分更新（`with`）およびリスト操作（`map`、`filter` 等）はつねに新しい値を返す。

**[value.no-cycles]** 無名関数（`fn`）は自己再帰のための名前を持たず、環境も不変であるため、値どうしの循環参照は発生しない。

**[eval.sandbox]** 正しい Rin のプログラムはホストプロセスをパニックさせない。ゼロ除算、整数オーバーフロー、境界外添字、型不一致、非網羅な `match`、および資源上限の超過は、すべて捕捉可能な評価エラーとしてホストへ返す。

## 2. 表記

### 2.1 規則の名前

規則には、`[src.encoding]` のような名前を付ける。名前は、節の番号が変わっても変わらない。

### 2.2 要件を表す言い方

- 「〜は字句エラーである」：字句解析が入力を受け付けず、位置と理由を返す。
- 「〜は構文エラーである」：構文解析が入力を受け付けず、位置と理由を返す。
- 「〜は実行時エラーである」：評価器が実行を中断し、位置と理由を返す。

## 3. 字句

**[src.encoding]** ソースコードは UTF-8 で書く。UTF-8 として正しくない入力は、字句エラーである。

**[src.token]** 識別子・リテラル・区切り記号・コメント・空白のいずれとしても読めない文字は字句エラーである。

**[src.newline]** 改行は LF である。CRLF は LF と同じに扱う。

**[src.comment]** 文字列リテラル・文字リテラルの外では、`;` から行の終わりまでをコメントとして読み飛ばす。改行がない場合はソース末尾までを読み飛ばす。

行末には `;`、行全体には `;;`、定義の説明には `;;;` を使う慣習とする。字句解析ではいずれも同じ行コメントとして扱う。

**[src.whitespace]** 文字列リテラル・文字リテラル以外では、ASCII 空白文字をトークンの区切りとして扱う。ただし、`[src.attached]` の隣接規則に該当する記号では、直前に空白やコメントがないことを区別する。

**[src.attached]** 直前に空白文字およびコメントを挟まずに現れた `(` と `[` は、直前の式に隣接したトークンとして扱う。
- `some(3)`、`ok(1)`、`err("ng")`、`Element.Gain(0.5)` の `(` は直前の識別子に隣接しなければならない。空白を挟んだ `some (3)` は 2 つの独立した式として読む。
- `xs[0]`、`(f x)[i]` の `[` は直前の識別子または `)` に隣接しなければならない。空白または `(` の後に現れた `[`（例：`[1, 2]`、`(+ [1] ...)`）はリストリテラルとして読む。

**[src.ident]** 識別子は、ASCII 英字・`_`・演算子記号（`+ - * / % = ! < >`）のいずれかで始まり、ASCII 英字・ASCII 数字・`_`・演算子記号が続く。大文字と小文字を区別する。先頭が大文字の識別子は、構造体名および列挙型名として扱う。

**[src.keywords]** 次の語は予約語または特殊リテラルである。

```text
def defn fn let if when match with import export
true false none some ok err inf nan
```

**[src.int]** 整数リテラルは、10 進数（任意の位置に `_` を含められる）、先頭に `-` を付けた負の整数、または `0x` / `0X` で始まる 16 進数で表し、`i64` として解釈する。`i64` の範囲を超えるリテラルは字句エラーである。

**[src.float]** 浮動小数点リテラルは、小数点 `.`（前後に数字が必要）または指数部 `e` / `E` を持つ数値として表し、`f64` として解釈する。

**[src.string]** 文字列リテラルは `"` で囲む。エスケープとして `\n`、`\r`、`\t`、`\\`、`\"`、`\'`、`\0` を認める。未閉鎖の文字列は字句エラーである。未知または未完のエスケープは `[src.escape]` に従う。

**[src.escape]** 文字列・文字リテラルで、上記以外のエスケープ、または `\` の直後で入力が終わる場合は字句エラーである。共通のエスケープ処理の診断にはこの規則名を付ける。

**[src.char]** 文字リテラルは `'` で囲まれた 1 文字（またはエスケープ 1 つ）で表す。

**[src.nesting-limit]** 構文木の深さ（リテラル・識別子・空リストなどの葉を 1 段と数えたノードの深さ。括弧・特殊形式・`{}`・`some(...)`・後置アクセス `.` / `[...]` ごとに 1 段増える。`let` の束縛リストや `match` の枝の括弧自体は段数に数えない）は最大 `256` 段までとし、上限を超える場合は構文解析中に検査して構文エラーを返す。上限を超えた時点でそれより内側や後ろの解析を止め、エラーには次の位置を示す。

- 入れ子の構文では、深さ 257 になる構文の先頭のトークンを示す（たとえば `(+ 1 ` を 256 重に開いた入力では 256 個目の `+`、`(+ 1 (+ 1 ...))` は括弧 255 重・深さ 256 まで許容され 256 重・深さ 257 でエラーになる）。
- 後置アクセス（`.` / `[...]`）では、その演算子（`.` または `[`）を示す。`x.a` を 256 回連ねた入力では 256 個目の `.` を示し、`x[x[…]]` のような index の値の入れ子でも深さ 257 になる 256 個目の `[` を示す。

**[src.nesting-guarantee]** スタック容量 256 KiB の環境において、上限（`256` 段）以内のソースに対しては、構文解析・バイトコード生成・AST の解放が構文の深さによるスタック枯渇で異常終了しない（実行時の値の構築・受け渡し・表示・解放といった値側の再帰は本保証の対象外とする）。上限を超えるソースは構文解析中に拒否し、バイトコード生成や評価器へ渡さない（入力全体の大きさによるメモリ不足は保証に含めない）。

## 4. 値と型

**[type.dynamic]** Rin は動的型付け言語であり、すべての値は自身の型を保持する。

**[type.numeric]** 数値型は 64 ビット符号付き整数 `i64` と 64 ビット浮動小数点数 `f64` の 2 種類のみとする。整数と浮動小数点数の暗黙の変換は行わない。

**[type.builtin]** 組み込みの値と型は次のとおりである。

- `void`：値を持たない結果（`def`、`defn`、`when` の戻り値）
- `i64`、`f64`、`bool`、`char`、`string`
- `list`：コンスセルからなる不変の連結リスト `[e1, e2, ...]` / `(list e1 e2 ...)`（`cons`、`car`、`cdr`、`len`、`is_empty` は O(1) で末尾を共有する）
- `array`：連続メモリ上に配置された固定長配列（`list->array` で生成し、`arr[i]`・`len`・`get` を O(1) で実行でき、FFI 境界との受け渡しに適する）
- `tuple`：2 要素以上の組 `(e1, e2, ...)`
- `struct`：名前と名前付きフィールドを持つ複合値 `Name { field: expr, ... }`
- `variant`：型名とバリアント名（および任意のペイロード 1 つ）を持つ値 `Type.Variant` / `Type.Variant(expr)`
- `option`：`none` または `some(expr)`
- `result`：`ok(expr)` または `err(expr)`
- `fn`：関数値（ユーザー定義関数・無名関数・組み込み関数）

## 5. 式と構文

**[src.syntax]** 式は本仕様の構文に従う。必要なトークン・識別子の欠落、閉じていない区切り、予期しないトークン、空の `()` は構文エラーである。個別の診断規則がない構文の不一致にはこの規則名を付ける。

**[expr.program]** プログラムは 0 個以上の式の並びである。先頭から順に評価し、最後の式の値をプログラムの結果とする。式が 0 個のときは `void` を返す。

**[expr.body]** `defn`・`fn`・`let`・`when` の本体と `match` の各枝には、1 つ以上の式が必要である。空の本体は構文エラーである。

**[expr.name]** 名前の参照・ホストからの関数呼び出しでは、名前が現在の環境で解決できなければ実行時エラーである。

### 5.1 定義と束縛

**[expr.def]** `(def name expr)` は、`expr` を評価した値を大域環境の名前 `name` に束縛し、`void` を返す。

**[expr.defn]** `(defn name (p1 p2 ...) body...)` は、仮引数 `p1, p2, ...` と本体 `body...` を持つ関数を定義し、大域環境の名前 `name` に束縛して `void` を返す。`defn` で定義した関数は、自身を含む大域環境の名前を参照して再帰呼び出しできる。

**[expr.fn]** `(fn (p1 p2 ...) body...)` は、現在のレキシカル環境を捕捉する無名関数値を返す。本体は 1 つ以上の式を持ち、順に評価して最後の式の値を返す。

**[expr.let]** `(let (x1 e1 x2 e2 ...) body...)` は、先頭から順に `e1, e2, ...` を評価して `x1, x2, ...` に束縛した局所環境で `body...` を評価し、最後の式の値を返す。

**[expr.module]** `(import mod_name)` は、ホストにより事前に読み込まれたモジュール `mod_name` を現在の環境に束縛し、`mod_name.symbol` の形式で公開シンボルを参照できるようにする（未読込のモジュールは実行時エラー）。`(export s1 s2 ...)` をモジュール内で記述した場合、指定されたシンボルのみが公開される（省略時はモジュール内の全 `def` / `defn` が公開される）。

未定義の公開シンボルの指定、非公開・存在しないシンボルへのアクセス、モジュール外の `export` は `[expr.module]` の実行時エラーである。

### 5.2 分岐とパターンマッチ

**[expr.condition]** `if` と `when` の条件は `bool` でなければならない。条件の型不一致にはこの規則名を付ける。

**[expr.if]** `(if cond then_expr else_expr)` は、`cond` を評価する。`bool` 以外の値は実行時エラーである。`true` なら `then_expr` のみを、`false` なら `else_expr` のみを評価して返す。第 3 引数（`else_expr`）は省略できない。

**[expr.when]** `(when cond body...)` は、`cond` が `true` のときのみ `body...` を順に評価し、つねに `void` を返す。

**[expr.match]** `(match scrutinee (pat1 body1...) (pat2 body2...) ...)` は、`scrutinee` を評価し、上から順にパターンと照合する。最初に一致した枝の `body...` を、パターンが束縛した変数を含む環境で評価して返す。いずれの枝にも一致しない場合は実行時エラーである。

**[pat.kinds]** パターンには次のものを書ける。

- `_`：任意の値に一致するワイルドカード
- `name`（小文字始まり）：任意の値に一致し、`name` に束縛する
- リテラル：整数、`true` / `false`、文字、文字列
- `none`、`some(name)`、`ok(name)`、`err(name)`（`name` には `_` も書ける）
- `Type.Variant`、`Type.Variant(name)`

### 5.3 データ構築・アクセス・不変更新

**[expr.list]** `[e1, e2, ...]`（要素間の `,` は任意）は、各要素を左から評価したリストを返す。

**[expr.tuple]** `(e1, e2, ...)` は、括弧内の最初の式の直後に `,` がある場合にタプルとして解析する。要素数が 1 のタプル構文はない。

**[expr.struct]** 先頭が大文字の識別子に `{` が続く `Name { f1: e1, f2: e2, ... }` は、構造体値を構築する。

**[expr.variant]** 先頭が大文字の識別子に `.` とバリアント名が続く `Type.Variant`、および隣接した `(` を伴う `Type.Variant(e)` は、バリアント値を構築する。

**[expr.field]** `expr.field` は、構造体値からフィールド `field` の値を読む。構造体でない場合、または存在しないフィールドを指定した場合は実行時エラーである。

**[expr.index]** `expr[index]`（`[` は直前に隣接）は、リスト・配列から `i64` 型の添字 `index` の要素を読む。対象がこれらの型でない場合、`index` が `i64` でない場合、負または要素数以上の場合は実行時エラーである。

**[expr.with]** `(with target { f1: e1, ... })` は、構造体 `target` の指定フィールドのみを新しい値で置き換えた構造体の複製を返す。`target` が構造体でない場合、または存在しないフィールドを含む場合は実行時エラーである。

### 5.4 関数呼び出し

**[expr.call]** `(callee arg1 arg2 ...)` は、`callee` および各引数を左から順に評価して関数を呼び出す。ただし、`and` および `or` は短絡評価を行う（[op.logic]）。呼び出し先が関数でない場合や、ユーザー定義関数の仮引数と実引数の数が一致しない場合は実行時エラーである。

## 6. 演算・組み込み関数

**[op.arith]** `+`、`-`、`*`、`/`、`%` は `i64` 同士または `f64` 同士に適用できる。`+` と `*` は 2 個以上の引数を受け取り左から畳み込む。単項 `(- x)` は符号反転を行う。
- `i64` の加算・減算・乗算・除算・剰余・符号反転でオーバーフローが生じる場合は実行時エラーである。
- `i64` の `/` および `%` で右辺が `0` の場合は実行時エラーである。

**[op.cmp]** `==`、`!=` は同じ型の値同士を比較して `bool` を返す。`<`、`<=`、`>`、`>=` は `i64` 同士または `f64` 同士を比較して `bool` を返す。異なる型同士の比較は実行時エラーである。

**[op.logic]** `and` と `or` は 1 個以上の `bool` 式を受け取り、左から短絡評価して `bool` を返す。`not` は 1 個の `bool` 値を否定する。

**[fn.convert]** `as_f64` は `i64` または `f64` を `f64` に変換する。`as_i64` は `i64` または `f64` を `i64` に変換する（`f64` が有限でない場合または `i64` の範囲外の場合は実行時エラーである）。

**[fn.math]** 組み込み定数 `pi`（円周率 `f64`）および組み込み関数 `sin`、`cos`、`sqrt`、`floor`、`ceil`（`f64 -> f64`）、`abs`（`i64 -> i64` または `f64 -> f64`）を提供する。

`abs` の `i64` 結果が範囲を超える場合は `[fn.math]` の実行時エラーである。

**[fn.list]** リスト操作として次の組み込み関数を提供する。すべてのリスト操作は元のリストを変更せず、新しいリストまたは値を返す。

- 基本・安全な参照
  - `(list e1 e2 ...)`：0 個以上の引数からリストを構築する。
  - `(len xs)`：`list`・`array` の要素数（O(1)）または `string` の文字数（`i64`）を返す。
  - `(is_empty xs)`：`xs` が空なら `true`、そうでなければ `false` を返す（O(1)）。
  - `(get xs i)`：`i` が範囲内なら `some(xs[i])`、範囲外なら `none` を返す。
  - `(car xs)`：先頭要素を `option`（`some` / `none`）で返す（O(1)）。
  - `(cdr xs)`：先頭を除いた残りのリストを末尾共有で返す（O(1)、空リストに対しては `[]` を返す）。
  - `(last xs)`：末尾要素を `option`（`some` / `none`）で返す。
- 構築・切り出し・連結
  - `(cons x xs)`：先頭に `x` を追加し、`xs` を末尾として共有する新しいリストを返す（O(1)）。
  - `(push xs x)`：末尾に `x` を追加した新しいリストを返す。
  - `(append xs ys ...)`：0 個以上のリストを順に連結した新しいリストを返す。
  - `(flatten xss)`：リストのリストを 1 段平坦化した新しいリストを返す。
  - `(slice xs start end)`：`start` 以上 `end` 未満の部分リストを返す（範囲外は実行時エラー）。
  - `(take xs n)` / `(drop xs n)`：先頭から `n` 個を取得、または `n` 個を除外したリストを返す（負数は実行時エラー）。
  - `(reverse xs)`：逆順にした新しいリストを返す。
  - `(range start end)`：`start` 以上 `end` 未満の `i64` のリストを返す（`end < start` のときは空リスト）。
- 検索・述語
  - `(contains xs v)`：`v` と等しい要素を含めば `true` を返す。
  - `(find f xs)`：述語 `f` が `true` を返す最初の要素を `option` で返す。
  - `(any f xs)` / `(all f xs)`：いずれか、またはすべての要素で `f` が `true` を返せば `true` を返す。
- 高階・変換・整列
  - `(map f xs)`：`xs` の各要素に 1 引数関数 `f` を適用した新しいリストを返す。
  - `(filter f xs)`：`xs` のうち述語 `f` が `true` を返した要素だけからなる新しいリストを返す。
  - `(flat_map f xs)`：各要素に `f`（リストを返す関数）を適用し、結果を 1 段平坦化した新しいリストを返す。
  - `(fold f init xs)`：初期値 `init` から左に 2 引数関数 `f(acc, x)` を畳み込んだ結果を返す。
  - `(zip xs ys)`：2 つのリストの要素を `(x, y)` タプルに組んだリストを返す（長さは短い方に合わせる）。
  - `(enumerate xs)`：各要素を `(i, x)` タプル（`i` は 0 始まりの `i64`）にしたリストを返す。
  - `(sort xs)` / `(sort_by key_fn xs)`：要素そのもの、または `key_fn` の戻り値で昇順に整列した新しいリストを返す（順序付けできない型・`NaN` は実行時エラー）。
  - `(unique xs)`：先頭から順に重複を除いた新しいリストを返す。
- 連続配列との相互変換
  - `(list->array xs)`：連結リスト `xs` を連続配列 `array` に変換する。
  - `(array->list arr)`：連続配列 `arr` を連結リスト `list` に変換する。

## 7. 評価規則・資源制限・エラー

**[eval.limits]** 評価器は 1 回の評価ごとに上限値 `Limits`（`steps`、`depth`、`memory_bytes`）を監視する。
- `steps`：式評価およびループ生成ごとのステップ数が上限を超えると `TooManySteps` エラーを返す。
- `depth`：ユーザー定義関数の呼び出しネスト深さが上限を超えると `TooDeep` エラーを返す（末尾呼び出し最適化が適用された呼び出しはネスト深さに数えない）。組み込み関数が呼ぶユーザー定義関数も数える。既定値（`200`）では、2 MiB のネイティブスタック上で上限内の実行と上限超過時のエラーを Debug / Release の両方で検証する。より大きな深さ上限や、より小さなスレッドスタックを使う場合の安全性は、実行環境に依存する。
- `memory_bytes`：確保された値の概算バイト数が上限を超えると `TooMuchMemory` エラーを返す。アロケータが要求された領域を確保できない場合も同じ種別・規則名で返す。
- 構文の入れ子上限（`[src.nesting-limit]`、`256` 段）は `Limits` とは独立した固定上限として構文解析時に検査する。

**[compile.capacity]** バイトコードの局所スロット数・捕捉変数の添字・引数や仮引数の数・リストやタプルの要素数など、内部の `u32` オペランドで表せない個数や添字は、コンパイル時に構文エラーとして拒否する。

**[host.value]** ホストから取り込む `Value::Builtin` の名前は実装済みの組み込み関数名でなければならない。未知の名前は実行時エラーである。

**[host.argument]** C API の引数検査で拒否する NULL 引数・不正 UTF-8 はホスト引数エラーである。詳細は [API 仕様](api.md#エラー情報の借用) に従う。

**[eval.error]** すべての `Error` は位置情報・種別・メッセージ・根拠となる規則名を保持する。ソース上の位置は 1 始まりの行・UTF-8 バイト単位の列位置であり、対応するソース位置を持たないホスト値の検証等では `0:0` を使う。規則名は角括弧を含めず `Error::rule()` から取得できる。

表示の先頭行は `L:C: message [rule.id]`、モジュール内では `module L:C: message [rule.id]` とする。呼び出し履歴があれば、その後の行に付ける。メッセージ自体には規則名を含めない。規則名は `spec.md` または [スキーマ仕様](schema.md) で定義する。演算や組み込み関数の引数の個数・型・値域の違反は、それぞれの `op.*` / `fn.*` 規則を用いる。子式や呼び出し先で発生したエラーの規則名はそのまま伝える。

**[eval.hints]** 名前・フィールド・公開シンボルの解決に失敗した場合、修正の手がかりをメッセージに付ける。種別・位置・規則名は元の診断のものを使う。

- 構造体のフィールド参照と `with` の不存在フィールドには `; fields: a, b`、モジュールの不存在公開シンボルには `; exports: a, b` を付ける。名前の辞書順（大文字小文字を区別する文字列順）で最大 16 件を表示し、残りがあれば `, ... and N more` を付ける。空なら `(none)` を表示する。公開シンボル一覧に非公開名を含めない。
- 未定義名には、近い名前があれば `; did you mean 'name'?` を付ける。候補はその参照位置で見える仮引数・`let`・パターンの束縛・外側のレキシカル変数、現在のモジュールの束縛、大域の束縛（組み込み関数・定数、import 済みのモジュール名を含む）から探す。未実行の定義、スコープ外の変数、ほかのモジュールの内部名、未 import のモジュール名は含めない。
- 距離は Unicode scalar 値単位の Levenshtein 距離（挿入・削除・置換を各 1）とする。入力名が 2 文字以下なら候補を出さず、3〜5 文字は距離 1 以下、6 文字以上は距離 2 以下を候補にする。同名を重複させず、距離の小さい順、同距離では名前順に最大 3 件を `; did you mean 'a', 'b', 'c'?` の形で表示する。該当する候補がなければヒントを付けない。
- 未読込のモジュールを `import` / ホストの `call_in` で指定した場合は、読み込み済みのモジュール名から同じ距離規則で候補を探す。ホストの `call` の未定義名には大域の束縛から候補を出し、`call_in` の不存在公開シンボルには公開一覧を付ける。
- 候補の検索とヒントの整形は失敗時に行う。ヒントは `Error.message` の一部とし、`Display` はその後に ` [rule.id]` を付け、呼び出し履歴を後続行に表示する。C FFI の `RinError.message` / `text` にも同じヒントを含める。

**[eval.snippet]** ホストが提供したソースの該当行に `^` キャレットを付けて、エラーとともに表示できる。`Error` 自体はソースを保持せず、明示的な整形 API の呼び出し時だけ処理する。

- 先頭行は `[eval.error]` の形式とし、直後に区切り行・行番号付きのソース行・キャレット行を付ける。1 回の表示で実際に出力するすべてのソース行の行番号から最大桁数を求め、行番号をその幅で右揃えにする。区切り行・キャレット行も同じ幅を使い、発生位置と全履歴で縦棒の位置を揃える。ソースなし・無効な位置・ホスト入口・省略されたフレームは幅の計算に含めない。ヒント・規則名・呼び出し履歴の内容を保ち、末尾の改行は付けない。
- ソースはモジュール名（モジュール外は `None`）からホストが選ぶ。発生位置には `Error::module()`、履歴の呼び出し位置には `StackFrame.caller_module` のソースを使う。ホストからの入口にはソース行を付けない。末尾呼び出し・反復の圧縮・中央のフレーム省略は既存の履歴表現を保つ。
- 列は UTF-8 バイト位置から、以下の範囲表による表示幅へ変換する。幅0の範囲を先に調べ、次に幅2の範囲を調べる。表にない文字は幅1とする。タブは、この表示幅でソース行の先頭から4桁区切りの空白に展開する。絵文字の並び（ZWJ連結・国旗・肌色修飾など）は補正せず、各文字の幅を合計する。表にない文字や端末の表示方式によっては、キャレットがずれる場合がある。

| 表示幅 | Unicodeの範囲（両端を含む） |
|---|---|
| 0 | U+0300–U+036F、U+200B–U+200F、U+3099–U+309A、U+FE00–U+FE0F |
| 2 | U+1100–U+115F、U+2E80–U+303E、U+3041–U+33FF、U+3400–U+4DBF、U+4E00–U+9FFF |
| 2 | U+A000–U+A4CF、U+AC00–U+D7A3、U+F900–U+FAFF、U+FE30–U+FE4F、U+FF00–U+FF60、U+FFE0–U+FFE6 |
| 2 | U+1F300–U+1F64F、U+1F900–U+1F9FF、U+20000–U+2FFFD、U+30000–U+3FFFD |

- 行は LF で分け、行末の CR は表示しない。その他の制御文字と U+2028 / U+2029 は Rust の `char::escape_default` の表記で表示する。キャレットにも同じ展開後の幅を使う。
- ソースを取得できない場合、行または列が 0、行・列が範囲外、列が UTF-8 文字の途中の場合は、その位置のソース行を省略する。行末の次の位置は許容し、末尾 LF の後の空行と空ソースの `1:1` も表示できる。

具体的な API は [API 仕様](api.md#16-ソース付きエラー表示) に従う。

## 8. 付録: 文法

```ebnf
Program    ::= Expr* EOF
Expr       ::= Primary ( "." IDENT | "[" Expr "]" )*
Primary    ::= INT | FLOAT | STRING | CHAR
             | "true" | "false" | "none" | "inf" | "nan"
             | ( "some" | "ok" | "err" ) "(" Expr ")"
             | UpperIdent "{" ( IDENT ":" Expr ","? )* "}"
             | UpperIdent "." IDENT ( "(" Expr ")" )?
             | "[" ( Expr ","? )* "]"
             | "(" Expr "," ( Expr ","? )* ")"
             | SpecialForm
             | "(" Expr Expr* ")"
             | IDENT
SpecialForm ::= "(" "def" IDENT Expr ")"
              | "(" "defn" IDENT "(" IDENT* ")" Expr+ ")"
              | "(" "fn" "(" IDENT* ")" Expr+ ")"
              | "(" "let" "(" ( IDENT Expr )* ")" Expr+ ")"
              | "(" "if" Expr Expr Expr ")"
              | "(" "when" Expr Expr+ ")"
              | "(" "match" Expr ( "(" Pattern Expr+ ")" )* ")"
              | "(" "with" Expr "{" ( IDENT ":" Expr ","? )* "}" ")"
Pattern    ::= "_" | INT | STRING | CHAR | "true" | "false" | "none"
             | ( "some" | "ok" | "err" ) "(" ( IDENT | "_" ) ")"
             | UpperIdent "." IDENT ( "(" ( IDENT | "_" ) ")" )?
             | IDENT
```


## テスト用の構文

**[test.deftest]** `(deftest "name" body...)` は名前付きテストを定義する。テストファイルのトップレベルでのみ使用でき、名前は文字列とする。同じファイル内の名前の重複は構文エラーとする。本体は空でもよい。通常の `eval` / `load_module` では、未実行の分岐内を含めて `deftest` を構文エラーとする。

**[test.check]** `(check expr)` は評価結果が `true` であることを検査する。`(check_eq actual expected)` は左から順に各引数を1回評価し、`==` と同じ規則で比較する。型が異なるなど、`==` がエラーになる比較は検査失敗ではなく実行時エラーとなる。両形式とも `deftest` の本体内だけで使用でき、成功・失敗のどちらでも `void` を返す。引数の数が不正な場合は構文エラーとする。検査失敗は記録して評価を続ける。通常の `eval` / `load_module` でこれらの形式を使用した場合は構文エラーとする。テスト用の形式は関数値として渡せない。同名の変数や仮引数は、束縛の有効範囲で通常の値として参照できる。呼び出しの先頭に書いた `check` / `check_eq` は特殊形式として扱う。

**[test.result]** テストの結果は成功・失敗・エラーの3種類とする。実行時エラーまたは資源上限超過があればエラー、そうでなく検査失敗があれば失敗、それ以外は成功とする。エラーが起きた場合も、それ以前の検査失敗を報告に残す。検査失敗には位置と実際の値・期待値を、実行エラーには通常の位置情報と呼び出し履歴を付ける。

ファイルの探索、実行環境の準備、CLIの出力形式は[テストツール仕様](testing.md)で定める。
