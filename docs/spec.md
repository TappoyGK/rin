# Rin 言語仕様

## 1. はじめに

Rin は、ホストプログラムに組み込んで安全に実行できる、小さな純粋関数型 Lisp 系言語である。Rin のプログラムは評価器（インタプリタ）上で実行され、ホストから明示的に渡された値のみを入力として受け取り、計算結果の値を返す。

### 1.1 範囲

Rin は次のものを含む。

- 値と型：`i64`、`f64`、`bool`、`char`、`string`、`ident`、`list`、`array`、`tuple`、`struct`、`variant`、`option`、`result`、`fn`、`void`
- 構文：`def`、`defn`、`fn`、`let`、`if`、`when`、`match`、`with`、`quote`、`quasiquote`、構造体リテラル、バリアントリテラル、リストリテラル、タプルリテラル、フィールド参照、添字アクセス、関数呼び出し
- 組み込み関数：算術・比較・論理・型変換・数学・リスト高階関数

Rin は次のものを含まない。

- 変数の再代入（`set!` 等）および可変なデータ構造
- ファイル I/O、ネットワーク、時刻、環境変数、標準出力、乱数などの暗黙の権限
- ホスト側関数へのコールバック（副作用は、操作を表す値を戻り値としてホストへ返すことで表現する）

### 1.2 安全性と不変性

**[value.immutable]** Rin のすべての値は不変である。束縛された名前への再代入はなく、構造体の部分更新（`with`）およびリスト操作（`map`、`filter` 等）はつねに新しい値を返す。

**[value.no-cycles]** 無名関数（`fn`）は自己再帰のための名前を持たず、環境も不変であるため、値どうしの循環参照は発生しない。

**[eval.sandbox]** 正しい Rin のプログラムはホストプロセスをパニックさせない。ゼロ除算、整数オーバーフロー、境界外添字、型不一致、非網羅な `match`、および資源上限の超過は、すべて捕捉可能な評価エラーとしてホストへ返す。

## 2. 表記

### 2.1 規則の名前

規則には、`[src.encoding]` のような名前を付ける。名前は、節の番号が変わっても変わらない。

### 2.2 要件を表す言い方

- 「〜は字句エラーである」：字句解析が入力を受け付けず、位置と理由を返す。
- 「〜は構文エラーである」：構文解析またはコンパイルが入力を受け付けず、位置と理由を返す。
- 「〜は実行時エラーである」：評価器が実行を中断し、位置と理由を返す。

## 3. 字句

**[src.encoding]** ソースコードは UTF-8 で書く。UTF-8 として正しくない入力は、字句エラーである。

**[src.token]** 識別子・リテラル・区切り記号・コメント・空白のいずれとしても読めない文字は字句エラーである。

**[src.newline]** 改行は LF である。CRLF は LF と同じに扱う。

**[src.comment]** 文字列リテラル・文字リテラルの外では、`;` から行の終わりまでをコメントとして読み飛ばす。改行がない場合はソース末尾までを読み飛ばす。

行末には `;`、行全体には `;;`、定義の説明には `;;;` を使う慣習とする。字句解析ではいずれも同じ行コメントとして扱う。

**[src.whitespace]** 文字列リテラル・文字リテラル以外では、ASCII 空白文字（空白 `U+0020`・タブ `U+0009`・LF `U+000A`・FF `U+000C`・CR `U+000D`）をトークンの区切りとして扱う。ただし、`[src.attached]` の隣接規則に該当する記号では、直前に空白やコメントがないことを区別する。

**[src.attached]** 直前に空白文字およびコメントを挟まずに現れた `(` と `[` は、直前の式に隣接したトークンとして扱う。
- `some(3)`、`ok(1)`、`err("ng")`、`Element.Gain(0.5)` の `(` は直前の識別子に隣接しなければならない。空白を挟んだ `some (3)` は 2 つの独立した式として読む。
- `xs[0]`、`(f x)[i]` の `[` は直前の識別子または `)` に隣接しなければならない。空白または `(` の後に現れた `[`（例：`[1 2]`、`(+ [1] ...)`）はリストリテラルとして読む。

**[src.ident]** 識別子は、ASCII 英字・`_`・演算子記号（`+ - * / % = ! < >`）のいずれかで始まり、ASCII 英字・ASCII 数字・`_`・演算子記号が続く（`'` は含まない）。識別子の直後に空白や区切りを挟まず `'` が続く場合（例：`y'`）は字句エラーである。大文字と小文字を区別する。先頭が大文字の識別子は、構造体名および列挙型名として扱う。

**[src.keywords]** 次の語は予約語または特殊リテラルである。

```text
def defn fn let if when match with import export
quote quasiquote unquote unquote_splicing
tuple field index variant struct
true false none some ok err inf nan
```

**[src.int]** 整数リテラルは、10 進数（任意の位置に `_` を含められる）、先頭に `-` を付けた負の整数、または `0x` / `0X` で始まる 16 進数で表し、`i64` として解釈する。`i64` の範囲を超えるリテラルは字句エラーである。

**[src.float]** 浮動小数点リテラルは、小数点 `.`（前後に数字が必要）または指数部 `e` / `E` を持つ数値として表し、`f64` として解釈する。

**[src.string]** 文字列リテラルは `"` で囲む。エスケープとして `\0`、`\n`、`\r`、`\t`、`\\`、`\"`、`\u{H}`（`H` は 1〜6 桁の 16 進数）を認める（`\'` は認めない）。未閉鎖の文字列は字句エラーである。未知・未完・範囲外（サロゲートまたは `U+10FFFF` 超）のエスケープは `[src.escape]` に従う。

**[src.escape]** 文字列リテラルのエスケープ（未知・未完、および `\u{H}` の空・未閉鎖・7 桁以上・範囲外）および文字リテラルの `\u{H}`（空・未閉鎖・7 桁以上・範囲外）が不正な場合は字句エラーである。共通のエスケープ処理の診断にはこの規則名を付ける。

**[src.char]** 文字リテラルは `\` で始め、直後の並びを次の順に当てはめて読む。

- `u{H}`（`H` は 1〜6 桁の 16 進数）：`H` が表す Unicode スカラー値（サロゲート・`U+10FFFF` 超・空・未閉鎖は `[src.escape]` の字句エラー。`\u` の後ろに `{` がなければ文字 `u` として読む）。
- 「文字か数字」（Unicode 一般カテゴリ L・M・Nd および `_`）が 1 つだけ：その文字（例：`\a`、`\n`（文字 `n`）、`\7`、`\日`、`\é`）。
- 「文字か数字」が 2 つ以上続く場合：名前つき文字 `\nul`（`U+0000`）・`\tab`（`U+0009`）・`\newline`（`U+000A`）・`\return`（`U+000D`）・`\space`（`U+0020`）。表にない名前（結合文字を伴う 2 スカラー値以上を含む）は字句エラーである。
- それ以外の 1 つの Unicode スカラー値（一般カテゴリ Z・Cc・Cf を除く）：その文字（例：`\(`、`\\`、`\"`、`\'`、`\😀`）。
- 一般カテゴリ Z（Zs・Zl・Zp）・Cc・Cf の文字、または入力末尾：字句エラーである（これらは名前つき文字か `\u{H}` で書く）。

文字リテラルは上記の並びを読み終えたところで終わり、直後の文字は次のトークンとして通常の字句規則で読む。文字列の中の `\` はエスケープを始め、文字リテラルの `\` はリテラルを始める。そのため、`"\n"` は改行を含む文字列で、`\n` は文字 `n` である。また `'` は `quote`、`` ` `` は `quasiquote`、`,` は `unquote`、`,@` は `unquote_splicing` トークンとして扱う。

**[src.nesting-limit]** 構文木の深さ（リテラル・識別子・空リストなどの葉を 1 段と数えたノードの深さ。括弧・特殊形式・`{}`・`some(...)`・後置アクセス `.` / `[...]` ごとに 1 段増える。`let` の束縛リストや `match` の枝の括弧自体は段数に数えない）は最大 `256` 段までとし、上限を超える場合は構文解析中に検査して構文エラーを返す。上限を超えた時点でそれより内側や後ろの解析を止め、エラーには次の位置を示す。

- 入れ子の構文では、深さ 257 になる構文の先頭のトークンを示す（たとえば `(+ 1 ` を 256 重に開いた入力では 256 個目の `+`、`(+ 1 (+ 1 ...))` は括弧 255 重・深さ 256 まで許容され 256 重・深さ 257 でエラーになる）。
- 後置アクセス（`.` / `[...]`）では、その演算子（`.` または `[`）を示す。`x.a` を 256 回連ねた入力では 256 個目の `.` を示し、`x[x[…]]` のような index の値の入れ子でも深さ 257 になる 256 個目の `[` を示す。

**[src.nesting-guarantee]** スタック容量 256 KiB の環境において、上限（`256` 段）以内のソースに対しては、構文解析・バイトコード生成・AST の解放が構文の深さによるスタック枯渇で異常終了しない。VM の関数呼び出し・高階組み込みコールバック・オブジェクトの解放も非再帰（`WorkArena` 上の明示スタックおよび侵入型解放キュー）で実行するため、構文・実行ともにネイティブスタックを線形消費しない（`std-value` 側の所有 `Value` 変換・表示は別途明示スタックで保護する）。上限を超えるソースは構文解析中に拒否し、バイトコード生成や評価器へ渡さない（入力全体の大きさによるメモリ不足は保証に含めない）。

## 4. 値と型

**[type.dynamic]** Rin は動的型付け言語であり、すべての値は自身の型を保持する。

**[type.numeric]** 数値型は 64 ビット符号付き整数 `i64` と 64 ビット浮動小数点数 `f64` の 2 種類のみとする。整数と浮動小数点数の暗黙の変換は行わない。

**[type.builtin]** 組み込みの値と型は次のとおりである。

- `void`：値を持たない結果（`def`、`defn`、`when` の戻り値）
- `i64`、`f64`、`bool`、`char`、`string`
- `ident`：不変の識別子名値（UTF-8 文字列と同じ内部表現。`'foo` のように表記する）
- `list`：コンスセルからなる不変の連結リスト `[e1 e2 ...]` / `(list e1 e2 ...)`（`cons`、`car`、`cdr`、`len`、`is_empty` は O(1) で末尾を共有する）
- `array`：連続メモリ上に配置された固定長配列（`list->array` で生成し、`arr[i]`・`len`・`get` を O(1) で実行でき、FFI 境界との受け渡しに適する）
- `tuple`：2 要素以上の組 `(tuple e1 e2 ...)`
- `struct`：名前と名前付きフィールドを持つ複合値 `Name { field: expr ... }` / `(struct Name (field expr) ...)`
- `variant`：型名とバリアント名（および任意のペイロード 1 つ）を持つ値 `Type.Variant` / `Type.Variant(expr)` / `(variant Type Variant)` / `(variant Type Variant expr)`
- `option`：`none` または `some(expr)` / `(some expr)`
- `result`：`ok(expr)` / `(ok expr)` または `err(expr)` / `(err expr)`
- `fn`：関数値（ユーザー定義関数・無名関数・組み込み関数）

**[value.display]** 値の表示（`Value`・`ValueRef` の `Display`）は型ごとに次の形式とし、関数値・`void`・`array`・`f64`（および `f64` を含む値）を除くデータ値はそのまま Rin のソースとして読み直したときに元の値と等しくなる表現を用いる。

- `void`：`void`
- `i64`：10 進表記（例：`42`、`-5`）
- `f64`：浮動小数点表記（整数値に小数点を付けず、`NaN`・`-0` 等を含むため再入力で元の `f64` 値に戻らない場合がある）
- `bool`：`true` または `false`
- `char`：文字リテラル表記（`\nul`・`\tab`・`\newline`・`\return`・`\space`、それ以外の一般カテゴリ Z・Cc・Cf・M の文字は `\u{H}`（小文字 16 進数、先頭の 0 なし）、それ以外は `\` に続けてその文字）
- `string`：`"hello"` 等の文字列リテラル表記（`\0`・`\n`・`\r`・`\t`・`\\`・`\"`、およびその他の一般カテゴリ Cc・Zl・Zp と `U+200C`・`U+200D`・`U+E0020`–`U+E007F` を除く Cf の文字を `\u{H}` でエスケープし、`'`・M・Zs は生のまま表示する）
- `ident`：`'foo`（先頭に `'` を付けた識別子名）
- `list`：`[e1 e2 ...]`（要素間は空白 1 個、空リストは `[]`）
- `array`：`#[e1 e2 ...]`（要素間は空白 1 個）
- `tuple`：`(tuple e1 e2 ...)`（要素間は空白 1 個）
- `struct`：`Name { f1: v1 f2: v2 ... }`（フィールド間は空白 1 個、フィールド名昇順、空の構造体は `Name {}`）
- `variant`：`Type.Variant` または `Type.Variant(v)`
- `option`：`none` または `some(v)`
- `result`：`ok(v)` または `err(v)`
- `fn`：`<builtin name>`・`<fn name>`・`<fn>` 等（再入力対象外）

## 5. 式と構文

**[src.syntax]** 式は本仕様の構文に従う。必要なトークン・識別子の欠落、閉じていない区切り、予期しないトークン、空の `()` は構文エラーである。個別の診断規則がない構文の不一致にはこの規則名を付ける。

**[expr.program]** プログラムは 0 個以上のトップレベル項目（宣言または式）の並びである。宣言は `def`・`defn`・`import`・`export` の 4 形式を指す。先頭から順に評価し、最後の項目の値をプログラムの結果とする。項目が 0 個のときは `void` を返す。本仕様で「トップレベル」とは、プログラム・モジュール・`deftest` 本体の最外側の並びを指す。

**[expr.body]** `defn`・`fn`・`let`・`when` の本体と `match` の各枝には、1 つ以上の式が必要である。空の本体は構文エラーである。

**[expr.name]** 名前の参照・ホストからの関数呼び出しでは、名前が現在の環境で解決できなければ実行時エラーである。

### 5.1 定義と束縛

**[expr.def]** `(def name expr)` は、`expr` を評価した値を大域環境の名前 `name` に束縛し、`void` を返す。トップレベルにのみ記述でき、関数本体や式の中に書いた場合は構文エラーである。

**[expr.defn]** `(defn name (p1 p2 ...) body...)` は、仮引数 `p1, p2, ...` と本体 `body...` を持つ関数を定義し、大域環境の名前 `name` に束縛して `void` を返す。`defn` で定義した関数は、自身を含む大域環境の名前を参照して再帰呼び出しできる。トップレベルにのみ記述でき、関数本体や式の中に書いた場合は構文エラーである。

**[expr.fn]** `(fn (p1 p2 ...) body...)` は、現在のレキシカル環境を捕捉する無名関数値を返す。本体は 1 つ以上の式を持ち、順に評価して最後の式の値を返す。

**[expr.let]** `(let (x1 e1 x2 e2 ...) body...)` は、先頭から順に `e1, e2, ...` を評価して `x1, x2, ...` に束縛した局所環境で `body...` を評価し、最後の式の値を返す。

**[expr.module]** `(import mod_name)` は、ホストにより事前に読み込まれたモジュール `mod_name` を現在の環境に束縛し、`mod_name.symbol` の形式で公開シンボルを参照できるようにする（未読込のモジュールは実行時エラー）。`(export s1 s2 ...)` をモジュール内で記述した場合、指定されたシンボルのみが公開される（省略時はモジュール内の全 `def` / `defn` が公開される）。複数の `export` の指定は合わせて扱い、同じシンボルを同一の `export` 内または複数の `export` にまたがって重複して指定した場合は、1 回指定したのと同じとする。`import`・`export` はトップレベルにのみ記述でき、関数本体や式の中に書いた場合は構文エラーである。

未定義の公開シンボルの指定、非公開・存在しないシンボルへのアクセス、モジュール外の `export` は `[expr.module]` の実行時エラーである。実行の段階では `[env.frozen]` と `[env.modules]` に従う。

**[env.phase]** 実行環境には、読み込みの段階と実行の段階がある。環境は読み込みの段階で作られ、凍結の操作によって実行の段階に移る。実行の段階から読み込みの段階には戻れない。読み込みの段階で実行の段階のソース評価（`rin_eval`・`rin_eval_with` 等）を行おうとした場合は、実行時エラーとする。定義済み関数の直接呼び出しは、ホスト API が許可する限りどちらの段階でも行える。

**[env.frozen]** 実行の段階で評価するソースに `def`、`defn`、`export`、`import` が含まれる場合は、位置（トップレベルか式の中か）によらずこの規則名による構文エラーとする。この判定は未実行の分岐や関数本体を含めて評価の前に行う。そのため、エラーになったソースは一部も実行されない。実行の段階でホストから大域束縛の追加・変更、モジュールの読み込み、または読み込みの段階の評価を行おうとした場合は、実行時エラーとする。実行の段階の評価は、大域環境と読み込み済みのモジュールを変更しない。

**[env.modules]** 実行の段階のモジュール外の評価では、凍結した時点で読み込まれているすべてのモジュールの公開シンボルを、`import` なしで `mod_name.symbol` の形式で参照できる（ただし同名の局所変数・初期束縛・大域束縛がある場合は `[env.isolation]` の優先順位に従う）。読み込みの段階でのモジュール間の `import` は、`[expr.module]` のとおりとする。

**[env.isolation]** 実行の段階の評価（`eval_with`）では、その 1 回の評価にだけ一時的に与える束縛（初期束縛）を指定できる。初期束縛は評価するソースおよびそこから呼ばれるモジュール外の関数から参照でき、モジュール内の関数からは参照されない。評価終了後（成功・失敗を問わず）に解放され、大域環境には残らない。モジュール外の名前解決は、局所変数・捕捉変数 → その評価の初期束縛 → 凍結された大域束縛（組み込みを含む） → 凍結時点で読み込み済みのモジュール名、の順に優先する。

実行の段階の評価結果は、評価するソース、初期束縛、`Limits`、数学関数の FMA 設定、凍結した時点の環境だけで決まる。それ以前やそれ以後の評価には左右されない。

### 5.2 分岐とパターンマッチ

**[expr.condition]** `if` と `when` の条件は `bool` でなければならない。条件の型不一致にはこの規則名を付ける。

**[expr.if]** `(if cond then_expr else_expr)` は、`cond` を評価する。`bool` 以外の値は実行時エラーである。`true` なら `then_expr` のみを、`false` なら `else_expr` のみを評価して返す。第 3 引数（`else_expr`）は省略できない。

**[expr.when]** `(when cond body...)` は、`cond` が `true` のときのみ `body...` を順に評価し、つねに `void` を返す。

**[expr.match]** `(match scrutinee (pat1 body1...) (pat2 body2...) ...)` は、`scrutinee` を評価し、上から順にパターンと照合する。最初に一致した枝の `body...` を、パターンが束縛した変数を含む環境で評価して返す。いずれの枝にも一致しない場合は実行時エラーである。

**[pat.kinds]** パターンには次のものを書ける。

- `_`：任意の値に一致するワイルドカード
- `name`（小文字始まり）：任意の値に一致し、`name` に束縛する
- リテラル：整数、`true` / `false`、文字、文字列、`'ident`（`ident` 値に一致）
- `none`、`some(name)`、`ok(name)`、`err(name)`（`name` には `_` も書ける）
- `Type.Variant`、`Type.Variant(name)`

### 5.3 データ構築・アクセス・不変更新

**[expr.list]** `[e1 e2 ...]` は、各要素を左から評価したリストを返す。正規 S 式形式は `(list e1 e2 ...)` である。

**[expr.tuple]** `(tuple e1 e2 ...)` は、2 要素以上のタプルを構築する。0 要素または 1 要素の `(tuple)` / `(tuple e1)` は構文エラーである。

**[expr.struct]** 先頭が大文字の識別子に `{` が続く `Name { f1: e1 f2: e2 ... }`、または正規 S 式形式 `(struct Name (f1 e1) (f2 e2) ...)` は、構造体値を構築する。同じフィールド名を複数回書いた場合は、すべての式を評価し、最後の値が有効になる。

**[expr.variant]** 先頭が大文字の識別子に `.` とバリアント名が続く `Type.Variant`、隣接した `(` を伴う `Type.Variant(e)`、または正規 S 式形式 `(variant Type Variant)` / `(variant Type Variant e)` は、バリアント値を構築する。

**[expr.field]** `expr.field` または正規 S 式形式 `(field expr field)` は、構造体値からフィールド `field` の値を読む。構造体でない場合、または存在しないフィールドを指定した場合は実行時エラーである。

**[expr.index]** `expr[index]`（`[` は直前に隣接）または正規 S 式形式 `(index expr index)` は、リスト・配列から `i64` 型の添字 `index` の要素を読む。対象がこれらの型でない場合、`index` が `i64` でない場合、負または要素数以上の場合は実行時エラーである。

**[expr.with]** `(with target { f1: e1 ... })` または正規 S 式形式 `(with target (f1 e1) ...)` は、構造体 `target` の指定フィールドのみを新しい値で置き換えた構造体の複製を返す。`target` が構造体でない場合、または存在しないフィールドを含む場合は実行時エラーである。同じフィールド名を複数回書いた場合は、すべての式を評価し、最後の値が有効になる。

**[expr.quote]** `'datum` または `(quote datum)` は、式を評価せずデータ値として返す。識別子・構文キーワードは `ident` 値、数値（`inf` / `nan` を含む）・`true` / `false` / `none`・文字・文字列はその値、`(a b ...)` は要素のリスト、`()` は空リスト `[]` となる。糖衣構文は正規 S 式（`[a b]` → `(list a b)`、`a.b` → `(field a b)`、`xs[i]` → `(index xs i)`、`some(x)` / `ok(x)` / `err(x)` → `(some x)` / `(ok x)` / `(err x)`、`Type.Variant` / `Type.Variant(x)` → `(variant Type Variant)` / `(variant Type Variant x)`、`Point { x: 1 }` → `(struct Point (x 1))`、`(with p { x: 1 })` → `(with p (x 1))`）へ正規化してからクォートする。

**[expr.quasiquote]** `` `datum `` または `(quasiquote datum)` は、`quote` と同様にデータ値を構築するが、深さに応じて `unquote` / `unquote_splicing` を評価する。深さは、その位置を囲む `quasiquote` の数から、囲む `unquote` / `unquote_splicing` の数を引いた値とする（どの `quasiquote` にも囲まれていない位置は深さ 0）。`quasiquote` の中の `quote` は深さを変えない（`` `(a '(b ,x)) `` の `,x` は評価される）。評価対象の `quasiquote` の中で、深さ 1 の位置に書いた `,expr` / `(unquote expr)` は `expr` を通常の式として評価して埋め込み、リスト要素位置の深さ 1 に書いた `,@expr` / `(unquote_splicing expr)` は `expr` をリストとして評価して展開する（評価される `expr` の中は深さ 0 になる）。深さ 2 以上の位置、または `quote` の中に書かれた `quasiquote` 内の深さ 1 以上の位置に書いた `unquote` / `unquote_splicing` は評価せずデータ（`['unquote ...]` / `['unquote_splicing ...]`）として構築する。深さ 0 の位置（どの `quasiquote` にも囲まれていない位置、および評価される `,expr` / `,@expr` の中を含む）に書いた `,` / `,@` / `(unquote ...)` / `(unquote_splicing ...)`、およびリスト要素位置以外の深さ 1 で評価される `,@` / `(unquote_splicing ...)` は構文エラーである。リスト要素位置とは `(...)` または `[...]` の直接の要素位置を指し、`'`・`` ` ``・`,`・`,@`・`(unquote ...)`・`some(...)`・構造体フィールド値・添字などの単一オペランド位置は含めない（たとえば深さ 2 の `,,@xs` も構文エラーである）。`,@expr` の評価結果が `list` でない場合は実行時エラーである。

### 5.4 関数呼び出し

**[expr.call]** `(callee arg1 arg2 ...)` は、`callee` および各引数を左から順に評価して関数を呼び出す。ただし、`and` および `or` は短絡評価を行う（[op.logic]）。呼び出し先が関数でない場合や、ユーザー定義関数の仮引数と実引数の数が一致しない場合は実行時エラーである。

## 6. 演算・組み込み関数

**[op.arith]** `+`、`-`、`*`、`/`、`%` は `i64` 同士または `f64` 同士に適用できる。`+` と `*` は 2 個以上の引数を受け取り左から畳み込む。単項 `(- x)` は符号反転を行う。
- `i64` の加算・減算・乗算・除算・剰余・符号反転でオーバーフローが生じる場合は実行時エラーである。
- `i64` の `/` および `%` で右辺が `0` の場合は実行時エラーである。

**[op.cmp]** `==`、`!=` は同じ型の値同士を比較して `bool` を返す。`<`、`<=`、`>`、`>=` は `i64` 同士、`f64` 同士、または `ident` 同士（Unicode コードポイント辞書順）を比較して `bool` を返す。異なる型同士（`ident` と `string` を含む）の比較は実行時エラーである。

**[op.logic]** `and` と `or` は 1 個以上の `bool` 式を受け取り、左から短絡評価して `bool` を返す。`not` は 1 個の `bool` 値を否定する。

**[fn.convert]** `as_f64` は `i64` または `f64` を `f64` に変換する。`as_i64` は `i64` または `f64` を `i64` に変換する（`f64` が有限でない場合または `i64` の範囲外の場合は実行時エラーである）。`ident->text` は `ident` を `string` に変換する。`text->ident` は `string` が識別子として有効なら `some(ident)`、無効なら `none` を返す。

**[fn.math]** 組み込み定数 `pi`（円周率 `f64`）および組み込み関数 `sin`、`cos`、`sqrt`、`floor`、`ceil`（`f64 -> f64`）、`abs`（`i64 -> i64` または `f64 -> f64`）を提供する。

`abs` の `i64` 結果が範囲を超える場合は `[fn.math]` の実行時エラーである。

`sin` と `cos` は [数学関数の決定的な計算手順](math-spec.md) に従う Rin 自身の実装で計算する。`Strict`（既定）と `Fused` のいずれの FMA 設定でも、すべての有限 `f64` 入力に対して真の値との差は 1 ulp 以内とする（正しく丸めた値とは限らない）。特殊値は `NaN`・`±inf` で `NaN`、`sin(±0.0) = ±0.0`、`cos(±0.0) = +1.0` を返す。絶対値が大きい有限引数には固定長の整数 Payne–Hanek 縮約を用い、引数の大きさによらず O(1)・動的確保なしで完了する。

**[fn.list]** リスト操作として次の組み込み関数を提供する。すべてのリスト操作は元のリストを変更せず、新しいリストまたは値を返す。

- 基本・安全な参照
  - `(list e1 e2 ...)`：0 個以上の引数からリストを構築する。
  - `(len xs)`：`list`・`array` の要素数（O(1)）または `string` の文字数（`i64`）を返す。
  - `(is_empty xs)`：`xs` が空なら `true`、そうでなければ `false` を返す（O(1)）。
  - `(get xs i)`：`i` が範囲内なら `some(xs[i])`、範囲外なら `none` を返す。
  - `(car xs)`：先頭要素を `option`（`some` / `none`）で返す（O(1)）。
  - `(cdr xs)`：先頭を除いた残りのリストを末尾共有で返す（O(1)、空リストに対しては `[]` を返す）。
  - `(last xs)`：末尾要素を `option`（`some` / `none`）で返す。
- 構築・切り出し・連結
  - `(cons x xs)`：先頭に `x` を追加し、`xs` を末尾として共有する新しいリストを返す（O(1)）。
  - `(push xs x)`：末尾に `x` を追加した新しいリストを返す。
  - `(append xs ys ...)`：0 個以上のリストを順に連結した新しいリストを返す。
  - `(flatten xss)`：リストのリストを 1 段平坦化した新しいリストを返す。
  - `(slice xs start end)`：`start` 以上 `end` 未満の部分リストを返す（範囲外は実行時エラー）。
  - `(take xs n)` / `(drop xs n)`：先頭から `n` 個を取得、または `n` 個を除外したリストを返す（負数は実行時エラー）。
  - `(reverse xs)`：逆順にした新しいリストを返す。
  - `(range start end)`：`start` 以上 `end` 未満の `i64` のリストを返す（`end < start` のときは空リスト）。
- 検索・述語
  - `(contains xs v)`：`v` と等しい要素を含めば `true` を返す。
  - `(find f xs)`：述語 `f` が `true` を返す最初の要素を `option` で返す。
  - `(any f xs)` / `(all f xs)`：いずれか、またはすべての要素で `f` が `true` を返せば `true` を返す。
- 高階・変換・整列
  - `(map f xs)`：`xs` の各要素に 1 引数関数 `f` を適用した新しいリストを返す。
  - `(filter f xs)`：`xs` のうち述語 `f` が `true` を返した要素だけからなる新しいリストを返す。
  - `(flat_map f xs)`：各要素に `f`（リストを返す関数）を適用し、結果を 1 段平坦化した新しいリストを返す。
  - `(fold f init xs)`：初期値 `init` から左に 2 引数関数 `f(acc, x)` を畳み込んだ結果を返す。
  - `(zip xs ys)`：2 つのリストの要素を `(tuple x y)` タプルに組んだリストを返す（長さは短い方に合わせる）。
  - `(enumerate xs)`：各要素を `(tuple i x)` タプル（`i` は 0 始まりの `i64`）にしたリストを返す。
  - `(sort xs)` / `(sort_by key_fn xs)`：要素そのもの、または `key_fn` の戻り値で昇順に安定整列した新しいリストを返す（順序付けできない型・`NaN` は実行時エラー。`cannot order A and B` の型名はリスト上で左にある要素を `A`、右にある要素を `B` として報告し、`sort_by` ではキーの型を報告する）。
  - `(unique xs)`：先頭から順に重複を除いた新しいリストを返す。
- 連続配列との相互変換
  - `(list->array xs)`：連結リスト `xs` を連続配列 `array` に変換する。
  - `(array->list arr)`：連続配列 `arr` を連結リスト `list` に変換する。

### 6.1 組み込み関数の処理量

**[eval.builtin-cost]** 組み込み関数の正常時の処理量の上限を定める。引数の式評価に加えて、以下の内部処理を `steps` に数える。[eval.cost-resources] に列挙する対象外の処理とコールバック本体を除き、内部の処理量は計上したステップ数の定数倍以内とする。この定数は入力の大きさに依存しない。処理量は実際のCPU命令数ではなく、走査する要素数やバイト数から決まる。同じ版の実装ではDebug / Releaseで同じ数え方を使う。

各呼び出しはまず1ステップを使う。次の表の「追加ステップ」はそれに加算する。`n` は入力の要素数、`m` は出力の要素数、`b` は文字列のUTF-8バイト数とする。長さが分かる走査・生成は、その処理を始める前にまとめて計上する。残りのステップ数で足りない場合、または計上する数が整数の範囲を超える場合は、呼び出し位置で `TooManySteps` を返す。

| 対象・条件 | 追加ステップ | 内部の計算量（最悪時） | 確保 | 利用者の制御（共通の `steps` 上限に加えて） |
|---|---|---|---|---|
| 固定個数の算術・数値の大小比較、`not`、数値変換、数学関数（`sin`・`cos` の大きい引数の縮約を含む） | 0 | O(1) | なし | 呼び出し回数 |
| `ident` の大小比較（`<`・`<=`・`>`・`>=`） | `min(b1, b2)` | O(min(b1, b2) + 1) | なし | 識別子名のバイト数 |
| `ident->text`・`text->ident` | `b` | O(b + 1) | 新しい文字列または `some(ident)` O(b) | 名前のバイト数 |
| `quasiquote` のリスト展開（`,@`、展開後の合計要素数 `m`） | `m`。組み込み呼び出しの基本費用 1 は加算しない | O(m + 1) | 一時領域・新しい節 O(m) | 展開するリストの長さ |
| `+`・`*`（引数 `k ≥ 2` 個） | `k − 2` | O(k) | なし | 引数の数 |
| 関数値として呼ぶ `and`・`or` | 判定した引数の数 | O(k) | なし | 引数の数・順序 |
| `len`（list / array）、`is_empty`、`car`、`cdr`、`cons`、`get`（array） | 0 | O(1) | `car`・`get` の `some`、`cons` の節を最大1個 | 呼び出し回数 |
| `len`（string） | `b` | O(b) | なし | 文字列のバイト数 |
| `get`（list、添字 `i ≥ 0`） | `min(i + 1, n)`。負の添字は0 | O(min(i + 1, n) + 1) | 結果の `some` を最大1個 | 添字。定数時間の参照にはarrayを使う |
| `last` | `n` | O(n + 1) | 一時領域O(n)、結果の `some` を最大1個 | 入力長 |
| `list`（引数 `n` 個）、`reverse` | `n` | O(n + 1) | 新しい節O(n) | 要素数 |
| `with`の構造体複製（元のフィールド数 `F`） | `F`。組み込み呼び出しの基本費用1は加算しない | 複製部分O(F + 1) | 新しいフィールド表O(F)。フィールドの値は共有 | 元のフィールド数 |
| `range` | `m = max(end − start, 0)` | O(m + 1) | 新しい節O(m) | 生成範囲 |
| `push` | `n + (n + 1)` | O(n + 1) | 一時領域・新しい節O(n + 1) | 入力長 |
| `append`（引数 `k` 個、合計長 `m`） | `k + 2m` | O(k + m + 1) | 一時領域・新しい節O(m) | 引数の数と合計長 |
| `flatten`（外側の長さ `n`、内側の合計長 `m`） | `n + 2m` | O(n + m + 1) | 一時領域O(n + m)、新しい節O(m) | 外側・内側の要素数 |
| `slice`・`take` | `n + m` | O(n + m + 1) | 一時領域O(n)、新しい節O(m) | 入力長・切り出し範囲 |
| `drop`（指定個数 `k ≥ 0`） | `min(k, n)` | O(min(k, n) + 1) | なし。残りの末尾を共有 | 除外個数 |
| `zip`（入力長 `a`, `b`、`m = min(a, b)`） | `a + b + m` | O(a + b + 1) | 一時領域O(a + b)、タプル・新しい節O(m) | 両方の入力長 |
| `enumerate` | `2n` | O(n + 1) | 一時領域・タプル・新しい節O(n) | 入力長 |
| `list->array` | `n` | O(n + 1) | 配列O(n) | 入力長 |
| `array->list` | `2n` | O(n + 1) | 一時領域・新しい節O(n) | 入力長 |
| `==`・`!=` | 下記の比較費用 `E` | O(E) | 比較待ちの値の組に応じた一時領域O(E) | 比較する値の大きさ |
| `contains` | `n + ΣE`（一致するまでの比較） | O(n + ΣE + 1) | 一時領域O(n)、比較の一時領域 | 入力長・比較する値の大きさ |
| `unique` | `n + m + ΣE`（既出要素との比較） | O(n² × Emax + 1) | 一時領域O(n)、新しい節O(m)、比較の一時領域 | 入力長・比較する値の大きさ |
| `find`・`any`・`all`・`fold` | `n + C` | O(n + 1)とコールバックの処理 | 一時領域O(n)、コールバックの結果 | 入力長・コールバック |
| `map`・`filter` | `n + m + C` | O(n + m + 1)とコールバックの処理 | 一時領域O(n + m)、新しい節O(m)、コールバックの結果 | 入力長・コールバック |
| `flat_map` | `n + 2m + C` | O(n + m + 1)とコールバックの処理 | 一時領域O(n + m)、新しい節O(m)、コールバックの結果 | 入力長・コールバックの出力長 |
| `sort` | `2n + S` | O(n log(n + 1) × (1 + bmax) + 1) | 一時領域・新しい節O(n) | 入力長・文字列長 |
| `sort_by` | `2n + S + C` | ソートの処理量とコールバックの処理 | 一時領域・新しい節O(n)、キーの値 | 入力長・キー関数・キーの文字列長 |

`C` は実際に呼んだコールバックのステップ数の合計であり、関数本体の式評価と、その中の組み込み関数の処理を含む。`find`・`any`・`all` は途中で判定が決まっても、入力の一覧を作るため `n` を計上する。直接書いた `and`・`or` は `[op.logic]` の短絡評価を行い、評価した式のステップだけを使う。

比較費用 `E` は次のように数える。値の組を調べるごとに1。同じ内部オブジェクトを共有する組はそこで比較を終える。異なるオブジェクトについては、リストは先頭・末尾、option / resultは中身へ進む。配列・タプルは長さが同じなら要素数を加えて比較待ちの組を作る。構造体は型名の比較費用を加え、名前とフィールド数が同じなら、逆のフィールド名順で各フィールドに1と名前の比較費用を加えて比較待ちの組を作る。列挙型は型名とバリアント名の比較費用を加え、一致すれば中身へ進む。文字列・名前の比較費用は双方のUTF-8バイト数の小さい方。比較待ちの値は配列・タプルの先頭、構造体のフィールド名順に調べ、不一致で終了する。`Emax` は1回の比較費用の最大値である。

ソート費用 `S` は `n < 2` なら0、それ以外は `n × ceil(log2(n)) × (1 + bmax)`。`bmax` は要素またはキーに含まれる文字列および `ident` 名の最大UTF-8バイト数で、いずれもなければ0とする。ソート開始前に計上し、入力の並びや整列の内部の比較回数では変えない。`sort_by` はキーを各要素につき1回計算してから計上する。

利用者は入力長・文字列長・入れ子の大きさ・コールバックを選び、`steps` でこれらの処理量を制限できる。リストを走査せずに参照したい場合はarrayを使える。値の確保および評価中の一時領域には `[eval.limits]` の `memory_bytes` も適用する。

構文解析・コンパイル、値の解放、診断、ホストとの受け渡し、評価の補助処理は追加ステップに含めない。それぞれの上限と扱いは次節に定める。

### 6.2 ステップに数えない処理

**[eval.cost-resources]** 処理量の上限を定める範囲と、定めない範囲を以下に示す。O記法は、明記した場合を除いて最悪時の内部処理量を表す。CPU時間や期限内の完了は保証しない。アロケータ・OS・ホストのコールバックの処理量には上限を定めない。

評価は、式・組み込み関数の処理と、本節に記載した準備・値の管理・診断だけを行う。ここに記載した上限を超える走査、コピー、回収を暗黙に追加してはならない。全値の定期走査、バックグラウンドGC、実行途中の再コンパイルは行わない。新しい処理を追加する場合は、ステップへの計上か、本節の上限・対象外の規定も追加する。

`steps`は準備や後始末を途中で打ち切る制限ではない。上限到達後も、所有する値の解放とエラーの生成を行う。`memory_bytes`は渡された `Allocator` 上の 3 領域（永続領域・オブジェクト領域・作業領域）の合計論理使用バイト数の上限であり、構文木・バイトコード・名前表・値・評価中の一時領域をすべて含む（固定長のインラインエラーストアと、`std-value` 経由でホストへ書き出す `Value` / `Error` 変換のみ対象外。また `Allocator` から取得するチャンク総量はブロック単位の切り上げにより `memory_bytes` を超えうる）。ホストはソースと受け渡す値の大きさ、保持する定義・モジュールの数を別に制限する。

#### 構文解析とコンパイル

**[compile.cost]** **処理量の上限を定める。** アロケータ内部の処理と失敗時の診断は別に扱う。ソースのUTF-8バイト数をS、処理前に`Builder`または`Machine`が保持するシンボルの個数と名前の合計バイト数をHとする。構文の深さは [src.nesting-limit] 以内とする。

| 項目 | 規定 |
|---|---|
| 対象・条件 | `eval`・`eval_with`・`load_module`が評価前に行う字句解析、構文解析、名前解決、バイトコード・診断用の名前情報の生成 |
| 内部の計算量 | 字句・構文の走査は最悪時 O(S+1)。シンボル表・モジュール表・構造体記述子表の検索・挿入は非暗号学的ハッシュ表（FNV-1a・線形探査）を用いるため、期待計算量は O(S+H+1)、ハッシュ衝突が集中する最悪時は名前数に比例した探査により O((S+H+1) × (N+1))（N は表の要素数）となりうる。構文の深さは固定上限以内なので、入れ子ごとの名前解決もこの範囲に含む |
| 確保 | 構文木・命令列・名前・位置情報はO(S+1)。今回必要な領域は既存のシンボル表を含めO(S+H+1)。渡された `Allocator` の作業領域（`WorkArena`）および永続領域（`PermArena`）を使い、`memory_bytes` の計上対象とする。作業領域のチャンクは評価終了時に先頭へ巻き戻して再利用する |
| 利用者の制御 | ホストがソース長と蓄積するシンボル数を制限する。定義を一度読み込み、`call`・`call_in`で呼べば各呼び出しでの解析・コンパイルを避けられる。`steps`=0でも準備は行う |

ハッシュ表は決定的な FNV-1a ハッシュを用い、乱数シードを使用しない（`[eval.determinism]` を満たす）。反復順は挿入順または辞書順ソートで決定し、ハッシュ表のバケット順に依存させない。

#### 値とコードの解放

**[value.release-cost]** **処理量の上限を定める。** アロケータ内部の解放処理は別に扱う。Rを解放する入口の参照数、Vを参照数が0になった値の個数、Eをその値が持つ要素・フィールド・捕捉値の総数とする。Kは最後の参照がなくなるコード・名前表の要素数と文字列の合計バイト数とする。

| 項目 | 規定 |
|---|---|
| 対象・条件 | 値の上書き、式の終了、関数からの復帰、上限到達・エラー時の巻き戻し、モジュール再読込に伴う参照の破棄 |
| 内部の計算量（最悪時） | O(R+V+E+K)。参照が残る値は参照数の更新だけを行い、中身を走査しない。参照数が0になった値は1回だけ解放し、その子への参照を1回ずつ処理する。値の文字列は内容を走査せず参照を外す |
| 確保 | プール内オブジェクトの解放は追加メモリ確保なし（O(1)）・非再帰で反復処理する。解放が新しいRinの値を作ることはない |
| 利用者の制御 | 大きな値の最後の参照を外す処理を、時間に余裕のある場所へ移せる。共有された子は参照が残る間は解放されない。`steps`による途中打ち切りは行わない |

`Builder`または`Machine`自体の破棄では、これに加えて、保持していた大域・モジュールのスロット、シンボル表、確保済み 3 領域のチャンク・プールスロットも処理する。それらの個数と保持データのバイト数に比例する。現在の`live_bytes`だけでは、過去に増えたスロットやチャンクを破棄する量は見積もれない。

#### エラーの生成と表示

**[error.cost]** **処理量の上限を定めない。** 失敗時の診断として扱い、`steps`に数えない。ソース取得コールバックと出力先の処理量もRinは制限しない。

| 項目 | 規定 |
|---|---|
| 対象・条件 | 未定義名の候補検索、利用可能な名前の一覧、呼び出し履歴、エラーメッセージとソース付き表示 |
| 内部の計算量（最悪時） | 候補数N・問い合わせ名の文字数Qについて、候補の距離計算はO(N(Q+1))。距離の閾値は最大2、保持する候補は最大3件。候補の列挙では空のスロットも含む束縛表の長さGに対してO(G+N)。一覧を整列する場合は別にO(N log(N+1) × (L+1))（Lは最大の名前のバイト数）を要しうる。表示する名前・メッセージのバイト数も加わる |
| 履歴とソース | 保持する履歴は最大64件だが、失敗した呼び出しを戻る処理自体は呼び出し数に依存する。ソース表示は表示位置ごとに先頭から該当行までを探す。各位置で読むソースのバイト数の合計をB、出力長をWとするとO(B+W)。同じモジュールのソースを複数回走査する場合がある |
| 確保 | コアのエラー本体と呼び出し履歴は固定長のインラインバッファ（`ErrorStore`）へ直接書き込むため、システムヒープを確保せず `memory_bytes` の対象外である。`std-value` 有効時の所有型 `Error` 変換およびソース付き文字列整形（`render` 等）のみホストヒープに O(W) を確保する |
| 利用者の制御 | ホストが識別子長・束縛数・ソース長を制限する。ソース付き表示を必要なときだけ行う。書き込み先へ直接出力すれば、表示全体の文字列を保持する必要はない |

#### 値の受け渡しと評価の補助処理

**[eval.support-cost]** **処理量の上限を定める。** アロケータ内部の処理、ホストが行う処理、上記の失敗時の診断は別に扱う。これらは組み込み関数の追加ステップとは別の費用であり、`steps`だけで一律には制限できない。

| 対象・条件 | 内部の計算量（最悪時）・確保 | 利用者の制御 |
|---|---|---|
| 作業配列・プール管理表の拡張 | 必要な容量が足りなくなった時に、保持中の配列要素Pと追加する要素Aに対してO(P+A+1)の領域確保・移動が起こりうる。要素にはVMのスロット、作業スタック、プールのチャンク参照を含む。容量が足りる時の追加は要素数に比例する。連続した追加の総費用は追加要素数に対して償却で線形だが、1回の拡張がO(1)とは限らない | ソース・値の大きさ、深さ、保持量を制限する。初回や過去の最大容量を超える処理で拡張が起こりうる |
| ホスト値の取り込み・結果の書き出し | 受け渡す値を木として展開した要素数と文字列バイト数をXとすると、フィールド表の構築・書き出しは期待値で O((X+1) log(X+2))、領域 O(X+1)。構造体の取り込みでは構造体記述子表のハッシュ検索を行うため、ハッシュ衝突が集中する最悪時は `[compile.cost]` と同様に記述子数に比例する探査が加わりうる。共有された値でも、書き出す各位置で子を展開する。内部の共有オブジェクトの個数だけからXを見積もらない | 引数・返り値の大きさと入れ子を制限する。繰り返し使う大きな入力は一度束縛する |
| 関数の入口・出口、クロージャの生成 | 引数・ローカルスロット・捕捉値の個数をAとすると、O(A+1)の初期化・参照更新。作業配列の拡張は次の共通規定による。値の中身は複製しない。解放は別途 [value.release-cost] | 関数の引数・ローカル・捕捉変数の数、呼び出し回数、`depth`を制限する |
| 構造体・モジュールの名前検索、構造体の生成・更新 | 対象の表の要素数F、名前の最大バイト数Lについて、構造体の生成はフィールド名の整列と重複の除去に O(F × (L+1) × log(F+2))（加えて構造体記述子表のハッシュ検索を行うため、ハッシュ衝突が集中する最悪時は `[compile.cost]` と同様に記述子数比例）。フィールド・公開名の検索と `with` の更新は、二分探索で 1 回につき O((L+1) log(F+2)) を項目数だけ繰り返す。生成は表を確保する。`with` の表の複製費用は [eval.builtin-cost] に含む | フィールド数・公開名の数・名前の長さ・更新項目数を制限する |
| リテラル・パターン・タプル・列挙値、通常のVM命令 | スカラー演算・スロット参照・ジャンプはO(1)。列挙した要素の保持やパターン検査は、そのソース内の要素数・文字列長に比例する。値の生成に必要な領域を確保する。リスト生成・添字参照・値比較の追加ステップは [eval.limits] に従う | ソースの大きさ・反復回数を制限する。実行した式は`steps`に数える |
| 大域・モジュールの定義・読込・公開表の作成 | 保持する名前数G・最大の名前長L・`export`で指定した名前の数F（重複を含む。`export`がない場合は公開する定義の数）について、スロットの拡張・列挙はO(G+1)、公開表の構築はシンボル表（ハッシュ表）の参照と公開名配列の整列および重複の除去 O(F(L+1) log(F+2)) を含む（ハッシュ衝突最悪時は表サイズ比例）。領域はスロット・名前・公開表の大きさに比例する。再読込では古い環境の解放も行う | 定義数・読込回数を制限し、読込済みの関数を呼び出す。読込はホストが渡したソースだけを使い、ファイル探索やネットワーク接続を行わない |


## 7. 評価規則・資源制限・エラー

**[eval.determinism]** 同じ実装版のRinに同じ操作を同じ順序で与えると、以下の条件のもとで同じ値、または同じエラーを返す。この規則はDebug / Releaseとプラットフォームの違いによらず適用する。

比較する入力には、ソース、ホストから渡す値と関数の引数、`Limits`、数学関数の FMA 設定（`MathFma`：`Strict` / `Fused`）、それ以前の `bind`・`load_module`・`eval`・`eval_with`・`freeze`・`call`・`call_in` の内容と実行順序を含める。途中で失敗した操作も含む。エラーの一致は、種別・位置・規則名・メッセージ・モジュール名・呼び出し履歴とその省略数までを対象とする。値の表示、候補名、フィールド名、公開シンボルの表示順も一致させる。ハッシュ表の乱数シードや反復順を結果へ反映してはならない。

条件と例外は次のとおり。

- 数学関数の FMA 設定（`Strict` / `Fused`）は組み込み数学関数（`sin`・`cos`）の内部計算のみに影響し、Rin プログラムの四則演算（`(+ (* a b) c)` 等）はどちらの設定でも融合しない。設定が異なれば結果が違いうるが、同じ設定のもとではビット単位で一致する。
- `f64` のNaNはNaNとして扱い、符号ビットとペイロードの一致は保証しない。NaN以外の `f64` は符号付きゼロを含めて同じ値を返す。この規定はNaNに対する `==` の結果を変えない。
- 必要なメモリをアロケータが確保でき、ホストが浮動小数点の丸めモードなど実行に必要な環境を変更しないことを前提とする。`memory_bytes` による 3 領域合計の論理使用バイト数上限検査は保証対象に含むが、実際の確保失敗は環境に依存する。同じ容量のArenaでも、アドレスのアラインメントや内部の配置によって確保の成否が異なることがある。
- VM の呼び出しフレームは作業領域（`WorkArena`）上に配置するため、関数呼び出しの深さによるネイティブスタック枯渇は起きない。必要なフレーム領域を確保できることのみを前提とする。

この規則は実行時間の一致や、`steps` だけで全処理量を制限できることを意味しない。ソース付きエラー表示には、ホストが提供するソースとコールバックの返り値も同じであることが必要である。

**[eval.limits]** 評価器は 1 回の評価ごとに上限値 `Limits`（`steps`、`depth`、`memory_bytes`）を監視する。
- `steps`：式評価ごとに1と、`[eval.builtin-cost]` の内部処理を計上し、上限を超えると `TooManySteps` エラーを返す。`with` は置き換える値の評価後、複製前に元のフィールド数分の費用を計上する。リストリテラルは要素数分の生成費用、リストの添字参照は `get` と同じ走査費用、`check_eq` は同じ比較費用 `E` も計上する。それぞれ、追加費用が上限を超えた位置をエラー位置とする。
- `depth`：ユーザー定義関数の呼び出しネスト深さが上限を超えると `TooDeep` エラーを返す（末尾呼び出し最適化が適用された呼び出しはネスト深さに数えない）。組み込み関数が呼ぶユーザー定義関数も数える。呼び出しフレームは作業領域（`WorkArena`）上で非再帰に管理するため、ネイティブスタック容量に依存せず、`depth` 上限と利用可能なメモリ（`memory_bytes`）の範囲内で任意の深さまで安全に実行できる。
- `memory_bytes`：3 領域（永続領域・オブジェクト領域・作業領域）の合計論理使用バイト数が上限を超えると `TooMuchMemory` エラーを返す。アロケータが要求された領域を確保できない場合も同じ種別・規則名で返す。`Allocator` から取得するチャンク総量はブロック単位の切り上げにより `memory_bytes` を超えうるため、固定容量アリーナ（`ArenaAllocator` 等）の容量は `MemoryConfig` のブロックサイズを踏まえて別に見積もる（参考：最小限の評価に必要な `memory_bytes` はリテラルで約 1 KiB、単純な算術式で約 1.6 KiB、関数定義を含む式で約 3.5 KiB 程度）。なお、読み込み段階（`Builder`）の評価では、初めて現れる大域名とモジュール名（定義か参照かを問わず、エラーになった評価も含む）、構造体リテラルに初めて現れる構造体名・フィールド名、および関数リテラル（`fn` / `defn`）のたびに永続領域（`PermArena`）へ追記され、`Builder` / `Machine` の破棄まで回収されない（再読み込み時は新しい `Builder` を作り直す。凍結後の `Machine` 評価では永続領域へ追記しない）。
- 構文の入れ子上限（`[src.nesting-limit]`、`256` 段）は `Limits` とは独立した固定上限として構文解析時に検査する。

**[compile.capacity]** バイトコードの局所スロット数・捕捉変数の添字・引数や仮引数の数・リストやタプルの要素数など、内部の `u32` オペランドで表せない個数や添字は、コンパイル時に構文エラーとして拒否する。

**[host.value]** ホストから取り込む `Value::Builtin` の名前は実装済みの組み込み関数名でなければならず、`Value::Ident`（および `val_ident`）の名前は `[src.ident]` を満たす有効な識別子でなければならない。違反する場合は実行時エラーである。

**[host.argument]** C API の引数検査で拒否する NULL 引数・不正 UTF-8 はホスト引数エラーである。詳細は [API 仕様](api.md#エラー情報の借用) に従う。

**[eval.error]** すべての `Error`（およびゼロヒープの `ErrorRef`）は位置情報・種別・メッセージ・根拠となる規則名を保持する。ソース上の位置は 1 始まりの行・UTF-8 バイト単位の列位置であり、対応するソース位置を持たないホスト値の検証等では `0:0` を使う。規則名は角括弧を含めず `Error::rule()` / `ErrorRef::rule()` から取得できる。

ゼロヒープ動作とメモリ不足時の安全な診断を保証するため、内部エラーストアは固定長のインライン領域を用いる。エラーメッセージ本体は最大 1024 バイトとし、超過分は UTF-8 文字境界で安全に切り詰める。呼び出し履歴の関数名・モジュール名を格納する文字列プールは最大 2048 バイトとし、あふれをまたぐ名前は UTF-8 文字境界で途中まで切り詰めて格納し、それ以降の名前は空文字列になる（空になった名前は `  in  (at L:C)` のように表示され、パニックやヒープ確保は行わない）。また、末尾呼び出しの省略回数および履歴フレームの行・列番号は 4,294,967,295（`u32::MAX`）で飽和する。

表示の先頭行は `L:C: message [rule.id]`、モジュール内では `module L:C: message [rule.id]` とする。呼び出し履歴があれば、その後の行に付ける。メッセージ自体には規則名を含めない。規則名は `spec.md` または [スキーマ仕様](schema.md) で定義する。演算や組み込み関数の引数の個数・型・値域の違反は、それぞれの `op.*` / `fn.*` 規則を用いる。子式や呼び出し先で発生したエラーの規則名はそのまま伝える。

**[eval.hints]** 名前・フィールド・公開シンボルの解決に失敗した場合、修正の手がかりをメッセージに付ける。種別・位置・規則名は元の診断のものを使う。

- 構造体のフィールド参照と `with` の不存在フィールドには `; fields: a, b`、モジュールの不存在公開シンボルには `; exports: a, b` を付ける。名前の辞書順（大文字小文字を区別する文字列順）で最大 16 件を表示し、残りがあれば `, ... and N more` を付ける。空なら `(none)` を表示する。公開シンボル一覧に非公開名を含めない。
- 未定義名には、近い名前があれば `; did you mean 'name'?` を付ける。候補はその参照位置で見える仮引数・`let`・パターンの束縛・外側のレキシカル変数、現在のモジュールの束縛、大域の束縛（組み込み関数・定数、import 済みのモジュール名を含む）から探す。実行の段階のモジュール外の評価では、その評価の初期束縛の名前と、凍結時点で読み込み済みのすべてのモジュール名も候補に含める。未実行の定義、スコープ外の変数、ほかのモジュールの内部名、読み込み段階で未 import のモジュール名は含めない。
- 距離は Unicode scalar 値単位の Levenshtein 距離（挿入・削除・置換を各 1）とする。入力名が 2 文字以下なら候補を出さず、3〜5 文字は距離 1 以下、6 文字以上は距離 2 以下を候補にする。同名を重複させず、距離の小さい順、同距離では名前順に最大 3 件を `; did you mean 'a', 'b', 'c'?` の形で表示する。該当する候補がなければヒントを付けない。
- 未読込のモジュールを `import` / ホストの `call_in` で指定した場合は、読み込み済みのモジュール名から同じ距離規則で候補を探す。ホストの `call` の未定義名には大域の束縛から候補を出し、`call_in` の不存在公開シンボルには公開一覧を付ける。
- 候補の検索とヒントの整形は失敗時に行う。ヒントは `Error.message` の一部とし、`Display` はその後に ` [rule.id]` を付け、呼び出し履歴を後続行に表示する。C FFI の `RinError.message` / `text` にも同じヒントを含める。

**[eval.snippet]** ホストが提供したソースの該当行に `^` キャレットを付けて、エラーとともに表示できる。`Error` 自体はソースを保持せず、明示的な整形 API の呼び出し時だけ処理する。

- 先頭行は `[eval.error]` の形式とし、直後に区切り行・行番号付きのソース行・キャレット行を付ける。1 回の表示で実際に出力するすべてのソース行の行番号から最大桁数を求め、行番号をその幅で右揃えにする。区切り行・キャレット行も同じ幅を使い、発生位置と全履歴で縦棒の位置を揃える。ソースなし・無効な位置・ホスト入口・省略されたフレームは幅の計算に含めない。ヒント・規則名・呼び出し履歴の内容を保ち、末尾の改行は付けない。
- ソースはモジュール名（モジュール外は `None`）からホストが選ぶ。発生位置には `Error::module()`、履歴の呼び出し位置には `StackFrame.caller_module` のソースを使う。ホストからの入口にはソース行を付けない。末尾呼び出し・反復の圧縮・中央のフレーム省略は既存の履歴表現を保つ。
- 列は UTF-8 バイト位置から、以下の範囲表による表示幅へ変換する。幅0の範囲を先に調べ、次に幅2の範囲を調べる。表にない文字は幅1とする。タブは、この表示幅でソース行の先頭から4桁区切りの空白に展開する。絵文字の並び（ZWJ連結・国旗・肌色修飾など）は補正せず、各文字の幅を合計する。表にない文字や端末の表示方式によっては、キャレットがずれる場合がある。

| 表示幅 | Unicodeの範囲（両端を含む） |
|---|---|
| 0 | U+0300–U+036F、U+200B–U+200F、U+3099–U+309A、U+FE00–U+FE0F |
| 2 | U+1100–U+115F、U+2E80–U+303E、U+3041–U+33FF、U+3400–U+4DBF、U+4E00–U+9FFF |
| 2 | U+A000–U+A4CF、U+AC00–U+D7A3、U+F900–U+FAFF、U+FE30–U+FE4F、U+FF00–U+FF60、U+FFE0–U+FFE6 |
| 2 | U+1F300–U+1F64F、U+1F900–U+1F9FF、U+20000–U+2FFFD、U+30000–U+3FFFD |

- 行は LF で分け、行末の CR は表示しない。その他の制御文字と U+2028 / U+2029 は Rust の `char::escape_default` の表記で表示する。キャレットにも同じ展開後の幅を使う。
- ソースを取得できない場合、行または列が 0、行・列が範囲外、列が UTF-8 文字の途中の場合は、その位置のソース行を省略する。行末の次の位置は許容し、末尾 LF の後の空行と空ソースの `1:1` も表示できる。

具体的な API は [API 仕様](api.md#16-ソース付きエラー表示) に従う。

## 8. 付録: 文法

```ebnf
Program    ::= TopItem* EOF
TopItem    ::= Decl | Expr
Decl       ::= "(" "def" IDENT Expr ")"
             | "(" "defn" IDENT "(" IDENT* ")" Expr+ ")"
             | "(" "import" IDENT ")"
             | "(" "export" IDENT* ")"
Expr       ::= Primary ( "." IDENT | "[" Expr "]" )*
Primary    ::= INT | FLOAT | STRING | CHAR
             | "true" | "false" | "none" | "inf" | "nan"
             | "'" Datum | "`" Datum
             | ( "some" | "ok" | "err" ) "(" Expr ")"
             | UpperIdent "{" ( IDENT ":" Expr )* "}"
             | UpperIdent "." IDENT ( "(" Expr ")" )?
             | "[" Expr* "]"
             | SpecialForm
             | "(" Expr Expr* ")"
             | IDENT
SpecialForm ::= "(" "fn" "(" IDENT* ")" Expr+ ")"
              | "(" "let" "(" ( IDENT Expr )* ")" Expr+ ")"
              | "(" "if" Expr Expr Expr ")"
              | "(" "when" Expr Expr+ ")"
              | "(" "match" Expr ( "(" Pattern Expr+ ")" )* ")"
              | "(" "with" Expr ( "{" ( IDENT ":" Expr )* "}" | ( "(" IDENT Expr ")" )* ) ")"
              | "(" "tuple" Expr Expr+ ")"
              | "(" "field" Expr IDENT ")"
              | "(" "index" Expr Expr ")"
              | "(" ( "some" | "ok" | "err" ) Expr ")"
              | "(" "variant" IDENT IDENT Expr? ")"
              | "(" "struct" IDENT ( "(" IDENT Expr ")" )* ")"
              | "(" ( "quote" | "quasiquote" ) Datum ")"
Pattern    ::= "_" | INT | STRING | CHAR | "'" IDENT | "true" | "false" | "none"
             | ( "some" | "ok" | "err" ) "(" ( IDENT | "_" ) ")"
             | UpperIdent "." IDENT ( "(" ( IDENT | "_" ) ")" )?
             | IDENT
Datum      ::= DatumPrimary ( "." IDENT | "[" Datum "]" )*
DatumPrimary ::= INT | FLOAT | STRING | CHAR
               | "true" | "false" | "none" | "inf" | "nan"
               | "'" Datum | "`" Datum | "," Datum | ",@" Datum
               | ( "some" | "ok" | "err" ) "(" Datum ")"
               | UpperIdent "{" ( IDENT ":" Datum )* "}"
               | UpperIdent "." IDENT ( "(" Datum ")" )?
               | "[" Datum* "]"
               | "(" "with" Datum "{" ( IDENT ":" Datum )* "}" ")"
               | "(" ( "quasiquote" | "unquote" | "unquote_splicing" ) Datum ")"
               | "(" Datum* ")"
               | IDENT
```


## テスト用の構文

**[test.deftest]** `(deftest "name" body...)` は名前付きテストを定義する。テストファイルのトップレベルでのみ使用でき、名前は文字列とする。同じファイル内の名前の重複は構文エラーとする。本体は空でもよく、本体の最外側（トップレベル）には宣言と式を書ける。通常の `eval` / `load_module` では、未実行の分岐内を含めて `deftest` を構文エラーとする。

**[test.check]** `(check expr)` は評価結果が `true` であることを検査する。`(check_eq actual expected)` は左から順に各引数を1回評価し、`==` と同じ規則で比較する。型が異なるなど、`==` がエラーになる比較は検査失敗ではなく実行時エラーとなる。両形式とも `deftest` の本体内だけで使用でき、成功・失敗のどちらでも `void` を返す。引数の数が不正な場合は構文エラーとする。検査失敗は記録して評価を続ける。通常の `eval` / `load_module` でこれらの形式を使用した場合は構文エラーとする。テスト用の形式は関数値として渡せない。同名の変数や仮引数は、束縛の有効範囲で通常の値として参照できる。呼び出しの先頭に書いた `check` / `check_eq` は特殊形式として扱う。

**[test.result]** テストの結果は成功・失敗・エラーの3種類とする。実行時エラーまたは資源上限超過があればエラー、そうでなく検査失敗があれば失敗、それ以外は成功とする。エラーが起きた場合も、それ以前の検査失敗を報告に残す。検査失敗には位置と実際の値・期待値を、実行エラーには通常の位置情報と呼び出し履歴を付ける。

ファイルの探索、実行環境の準備、CLIの出力形式は[テストツール仕様](testing.md)で定める。
