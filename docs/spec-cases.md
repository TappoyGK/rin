# Rin 仕様例集

[言語仕様](spec.md)に対する受理・拒否・評価結果の確認例。各例は `rin/tests/spec_cases.rs` によって自動的に読み込まれ、規則 ID の存在・ID の一意性・件数表・評価結果が検証される。

## 分類と件数

| 分野 | ファイル | 接頭辞 | 件数 |
|---|---|---|---|
| 字句 | [lex.md](spec-cases/lex.md) | `lex` | 12 |
| 式と構文 | [expr.md](spec-cases/expr.md) | `expr` | 17 |
| リストと配列 | [list.md](spec-cases/list.md) | `list` | 6 |
| 演算・制限・エラー | [eval.md](spec-cases/eval.md) | `eval` | 24 |

## 書式

- 各例は `### ID 題名` で始める（`ID` は `接頭辞-3桁番号`）。
- 本文に `主根拠：` に続けて `spec.md` の規則 ID をバッククォート付きの角括弧で記載する（例：`` 主根拠：`[src.attached]` ``）。
- エラーになる例には `` 期待規則：`[rule.id]` `` を記載し、実際のエラーの規則名と完全一致で検証する。`主根拠` は例の主題、`期待規則` は診断の直接の根拠を示す。
- エラーメッセージを検証する例には `` 期待メッセージ：`本文` `` を記載し、`Error.message` と完全一致で検証する（位置・規則名・呼び出し履歴は含めない）。
- ソース付き表示を検証する例には `**期待表示：**` と `text` コードブロックを記載し、`Error::render` の結果と完全一致で検証する。
- 事前環境の構築が必要な例では、以下の任意欄を置ける（`arena=N` の上限指定とは組み合わせられない）。
  - `**モジュール `name`：**` の直後に `rin` コードブロックを置くと、事前に `Builder::load_module(name, ...)` で読み込む（複数記載可）。
  - `**読み込み：**` の直後に `rin` コードブロックを置くと、事前に `Builder::eval` で評価する（1 つまで）。
  - `**失敗する読み込み：**` の直後に `rin` コードブロックを置くと、`Builder::eval` が失敗することを検証したうえで同じ `Builder` を使う（1 つまで）。
  - `` 初期束縛：`name = expr` `` を記載すると、事前構築後に `Builder::freeze()` で凍結し、`Machine::eval_with` に初期束縛を渡して `**入力：**` を評価する。複数の初期束縛を渡す場合は `初期束縛：` 行を並べて記載する（1 行につき 1 件、`expr` は読み込み環境とは独立した新しい環境で `rin::eval` により評価する）。
  - 実行順序は記載順によらず、モジュール（記載順）→ 読み込み → 失敗する読み込み → 入力 とする。`初期束縛：` がない場合は凍結せず、同じ `Builder` 上で `Builder::eval` により `**入力：**` を評価する。
- `**入力：**` の直後に `rin` コードブロックを 1 つ置く（各見出しの直後に対応するコードブロックがない場合や、未知の `**...：**` 見出し・重複する入力ブロックがある場合は検証エラーとする）。
- `**期待結果：**` の直後に次の 3 列からなる表を置く。

| 列 | 値 |
|---|---|
| 上限 | `既定`、`steps=N`、`depth=N`、`arena=N` |
| 結果 | `値`、`字句エラー`、`構文エラー`、`実行時エラー`、`ステップ超過`、`深さ超過`、`メモリ超過` |
| 値 | `結果` が `値` の場合は期待値を表す Rin 式、エラーの場合は `—` |
