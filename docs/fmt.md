# フォーマッタ仕様

`rin fmt` はRinのソースを共通の書式に整える。設定ファイルや外部クレートを必要としない。

## 書式

- 字下げは空白2個。1行に収まる式は1行にし、100文字を超える式は改行する。幅はUnicodeスカラー値の個数で数える。
- リテラルの中身とコメント本文は折り返さない。長い識別子、リテラル、コメントや深い字下げなど、分割できない部分は100文字を超えることがある。
- 末尾の改行は1個にする。コードの改行はLFに統一し、リテラル内部の改行は原文を保つ。複数行文字列リテラル（`"""..."""`）は開始引用符から閉じ引用符まで原文を保持し、内部の改行・内容・閉じ引用符までの字下げを変えない（開始引用符より前のコードの字下げは整形する）。
- トップレベルの連続する定義（`def`・`defn`・`defschema`・`deftest`）の間には空行を1行入れる。定義の直前のコメントは定義と一緒に置く。既存の空行は1行にまとめて保持し、ファイル先頭の空行は取り除く。
- 複数行の `defn`・`fn`・`let`・`when`・`defschema`・`deftest` では、ヘッダの後に本体を2個の空白で字下げする（`defn`・`fn` に `-> R` がある場合は `-> R` までをヘッダとする）。閉じ括弧は最後の要素の後ろにまとめる。ただし行コメントの後では、閉じ括弧を次の行に置く。
- 複数行の `let` は名前と値を組にして、各束縛の先頭を揃える。
- 複数行の `match` は枝を分け、枝の本体も収まらなければ2個の空白で字下げする。
- 複数行の `if` と通常の呼び出しは、2個目以降の引数を最初の引数の位置に揃える。最初の引数が行に収まらない場合は、改行して2個の空白で字下げする。
- リスト、構造体の要素は空白で区切る（カンマは使わない）。タプル `(tuple e1 e2 ...)` は通常の S 式として整形する。複数行の構造体は1フィールドずつ改行する。1行の構造体は `{` の内側に空白を1個入れる。
- 行末コメントの前は空白1個。行全体のコメントは周囲のコードに合わせて字下げする。先頭の `;`・`;;`・`;;;` と本文の間に空白がなければ1個追加する。セミコロンの個数と本文、前後のコードとの順序は保つ。
- `some(x)`、`Kind.Variant(x)`、`i64(n)` 等の型パターン、`xs[i]` の隣接関係、`'`・`` ` ``・`,`・`,@` と直後のオペランドの密着、および文字列・文字リテラルの原文を保つ。

例えば、`[ 1  2 3 ]` は `[1 2 3]` になる。短い定義は `(defn double ((x i64)) -> i64 (* x 2))` のように1行にする。

`defhook` の書式は、該当の言語構文を実装する際に追加する。部分的に整形を無効にする指定は設けない。

## 構文の保存

**[fmt.preserve]** 整形前後のソースを既存の構文解析器で解析し、位置情報を除いたAST（型注釈および `defschema` を含む）が同じであることを検査する。浮動小数点リテラルはNaN・負のゼロを含めてビット表現を比較する。整形後の構文解析に失敗するか、ASTが異なる場合はエラーとし、整形結果を返さない。

構文解析エラーのある入力は、元の位置と規則を持つエラーを返す。テストファイルの `deftest`・`check`・`check_eq` にも対応し、テスト構文の配置や引数も検査する。コンパイル時の検査（`def`・`defn`・`defschema`・`import`・`export` の配置や容量検査）、名前解決、型検査、実行は行わない。

## CLI

```sh
rin fmt
rin fmt src tests
rin fmt --check
rin fmt -
```

- `rin fmt [PATH...]`：直接指定したファイル（拡張子は問わない）とディレクトリ以下の `*.rin` を整形し、その場で書き換える。省略時はカレントディレクトリ。テストファイルも対象とする。
- `--check`：書き換えず、整形が必要なファイルのパスを標準出力に1行ずつ表示する。すべて整形済みなら終了コード0、整形が必要なら1。
- `-`：標準入力から読み、整形結果を標準出力へ出す。他のパスとは併用しない。`--check -` は整形が必要なら `-` と表示して終了コード1を返す。
- `--help`：使い方を表示する。
- `--`：以降をパスとして扱う。`-` という名前のファイルは `./-` または `-- -` として指定する。

不明・重複したオプションはエラー。引数・読み取り・構文・書き込みのエラーは標準エラーに表示し、終了コード2を返す。オプション値の `=` 形式は使わない。

探索順は正規化したパス順。重複はまとめ、`.git`・`target` とシンボリックリンクは辿らない。シンボリックリンクを直接指定した場合は、終了コード2のエラーとする。全ファイルの構文とASTを検査してから書き換えるため、構文エラーがあればどのファイルも変更しない。

変更が必要なファイルだけを、同じディレクトリの一時ファイル経由で置き換える。ファイルのアクセス権は保持し、読み取り専用ファイルは拒否する。書き込みの途中でI/Oエラーが起きた場合、それ以前に処理したファイルの変更は残る。

## Rust API

```rust
pub fn rin::fmt::format(source: &str) -> Result<String, Error>;
```

成功時は整形済みのソースを返す。同じ結果をもう一度整形しても変化しない。空の入力には改行1個を返す。
