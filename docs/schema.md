# Rin スキーマ仕様

Rin の値（`Value`）がホスト側の期待する形に適合するかを検証するための、軽量なスキーマ専用言語（Rin Schema DSL）を定める。

## 1. 構成

**[schema.program]** プログラムは 0 個以上の名前付きスキーマ定義 `(defschema Name TypeExpr)` と、末尾の 1 つのルート型式 `TypeExpr` からなる。

```rin
(defschema Element (variant Element (Plain) (Fire) (Frost)))
(defschema Card (struct Card (id string) (cost i64) (element Element)))
(list Card)
```

## 2. 型式（`TypeExpr`）

**[schema.syntax]** 型式は以下の構文に従う。必要な名前・区切り・型式の欠落や余分なトークンは構文エラーである。字句解析は Rin と共通であり、字句エラーは `src.*` の規則名を用いる。

**[schema.type]** 値の種類は要求された型に一致し、コンテナの要素は対応する型に適合しなければならない。構造体・バリアントの型名も一致しなければならない。型・型名の不一致は検証エラーである。

### 2.1 プリミティブ・ワイルドカード

- `void`、`i64`、`f64`、`bool`、`char`、`string`
- `any`：任意の型・値を受け入れる。

### 2.2 コンテナ・合成型

- `(list T)`：全要素が `T` に適合する `list`
- `(array T)`：全要素が `T` に適合する `array`
- `(tuple T1 T2 ...)`：要素数が一致し、各要素が `T1, T2, ...` に適合する `tuple`（2 要素以上）
- `(option T)`：`none`、または値が `T` に適合する `some(v)`
- `(result T E)`：値が `T` に適合する `ok(v)`、または `E` に適合する `err(e)`

**[schema.tuple]** タプル型式には 2 個以上の要素型が必要である。検証するタプルの要素数は型式と一致しなければならない。

### 2.3 構造体（厳格・開放の選択）

**[schema.struct]** 構造体のフィールドは次の条件に従う。必須フィールドの欠落や厳格な構造体の余剰フィールドは検証エラーである。

- `(struct Name (f1 T1) (f2 T2) ...)`（厳格）：構造体名が `Name` に一致し、定義された全フィールドが揃い、**かつ未定義の余剰フィールドが存在しない**こと。
- `(open_struct Name (f1 T1) (f2 T2) ...)`（開放）：構造体名が `Name` に一致し、定義された全フィールドが存在して型が適合すること（**余剰フィールドは許容する**）。

### 2.4 バリアント・名前参照

**[schema.variant]** バリアントのケース名とペイロードの有無は型式と一致しなければならない。

- `(variant Name (V1) (V2 T) ...)`：バリアント型名が `Name` に一致し、バリアント名およびペイロードの有無・型が一致すること。

**[schema.reference]** 参照する名前は `defschema` で定義されていなければならない。未定義名はスキーマ解析時に構文エラーとして拒否する。

- `Name`：`defschema` で定義されたスキーマを参照する（自己再帰・相互参照を許す）。

**[schema.productive]** 名前参照の自己再帰・相互再帰では、同じ値に対して同じ名前を繰り返し検証する循環は検証エラーである。コンテナの子の値へ進む再帰は許容する。

### 2.5 入れ子の上限

型式の構文入れ子は最大 `256` 段までとし、上限を超える場合は `[src.nesting-limit]`（[言語仕様](spec.md)）の構文エラーを返す。

検証エラーは `Runtime`、位置は `0:0` とし、規則名を `Error::rule()` と表示文字列で返す。
