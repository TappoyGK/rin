# テストツール仕様

テストの構文は言語仕様の `[test.deftest]`・`[test.check]`・`[test.result]` に従う。実行器はRust API `rin::test::run` とCLI `rin test` から利用できる。

## テストファイル

```rin
;; arithmetic_test.rin
(defn double (x) (* x 2))

(deftest "2倍にする"
  (check_eq (double 3) 6)
  (check (== (double 0) 0)))
```

テストごとに新しい `Machine` と `HeapAllocator` を作る（数学関数の FMA 設定は常に既定の `MathFma::Strict` を使う）。提供されたモジュールを読み込み、テストファイルの `deftest` 以外のトップレベル式を記載順に評価してから、対象テストの本体を実行する。他のテストの定義や値は引き継がない。トップレベル式が `deftest` の後に書かれていても、準備として本体より先に評価する。

ファイル内のテストは記載順に実行する。構文や配置が不正なテストを含むファイルは、そのファイル全体を実行せずエラーとして報告する。他のテストファイルは続けて処理する。フィルタで除外されるテストも構文検査する。

`Limits` は各テストの準備式と本体を合わせた1回の評価に適用する。モジュールの読み込みはそれぞれ独立した評価として同じ上限を適用する。ソース解析・コンパイル・結果報告のためのホスト側のメモリは、現在の評価器と同様に `memory_bytes` の対象外である。

## モジュール

**[test.modules]** 実行器に渡すモジュール名は重複してはならない。モジュール内の `import` を構文上すべて調べ、参照先を先に読み込む。参照先の不足・循環・名前の重複は準備段階のエラーとし、テストを実行しない。モジュールの構文エラーも同様に扱う。読み込み時の評価エラーは、その環境を使うテストのエラーとして報告する。

CLIでは `--module-path` 内の `.rin` ファイルを再帰的に集める。`*_test.rin` はモジュールとして読み込まない。ファイル名から拡張子を除いたものをモジュール名とし、親ディレクトリ名は名前に含めない。テストファイルからは `(import game)` のように参照する。

## CLI

```sh
cargo run -p rin-cli -- test
cargo run -p rin-cli -- test tests --module-path modules --filter 攻撃
cargo run -p rin-cli -- test tests --format json
```

| 引数 | 動作 |
|---|---|
| `test [PATH...]` | ファイル、または再帰探索するディレクトリを指定する。省略時はカレントディレクトリ。ディレクトリ内では `*_test.rin` を探す。明示したファイルは `.rin` であれば実行する。 |
| `--module-path DIR` | モジュールの探索先。複数回指定できる。省略時はモジュールを読み込まない。 |
| `--filter PATTERN` | 大文字・小文字を区別したテスト名の部分一致。 |
| `--steps N` | ステップ上限。既定100,000。 |
| `--depth N` | 呼び出し深さ上限。既定200。 |
| `--memory N` | 評価器のメモリ上限。バイト数または `K` / `M` / `G`（1024の累乗）を付けて指定する。既定16 MiB。 |
| `--format text\|json` | 表示形式。既定text。 |

Suzと同じく、オプション値は `--名前 値` のように別の引数で渡す。`--名前=値` は受け付けない。`--module-path` 以外のオプションの重複と、不明なオプションはエラーとする。`--` 以降は、`-` で始まる名前もパスとして扱う。パスはOS文字列のまま保持する。

`rin --help` は全体の使い方、`rin test --help` はtestの使い方、`rin --version` はバージョンを表示する。トップレベルの情報表示オプションは単独で指定する。`--steps` / `--depth` は0以上の10進整数とし、符号・小数・範囲外の数値は受け付けない。`--memory` も同様だが、大文字の `K`・`M`・`G` を末尾に付けられる。換算結果の範囲超過もエラーとする。

探索時は `.git`・`target` ディレクトリとシンボリックリンクを辿らない。重複したパスは正規化後にまとめ、パス順に処理する。テスト0件も成功とする。

終了コードは、全件成功なら0、検査失敗・評価エラー・テスト構文エラー・モジュール依存エラーがあれば1、引数不正やファイル読み取りエラーなら2。引数不正の案内は標準エラーに出す。それ以外のテスト結果は標準出力へ出す。

text形式では、テストの名前とファイル、失敗した検査の該当行とキャレット、実際の値と期待値を表示する。評価エラーはモジュールのソースと呼び出し履歴も表示する。

## JSON出力

標準出力にJSONオブジェクトを1つ出す。

- `success`：全件成功ならtrue。
- `tests`：`source`、`name`、`line`、`column`、`status`（`ok` / `FAIL` / `ERROR`）、`failures`、`error`。
- `failures`：位置の `line`・`column`、`check`（`check` / `check_eq`）、`actual`・`expected`。値はRinの表示形式の文字列とする。
- `error`：成功時・検査失敗のみの場合はnull。エラー時は `kind`、`rule`、`message`、`line`、`column`、`module`、`display`、`backtrace`。
- `backtrace`：各フレームの `module`、`name`、`caller_module`、`line`、`column`、`display`。省略された末尾呼び出し等の情報は `display` に含む。
- `errors`：準備段階のエラーを `source` と `error` の組で格納する。ファイル読み取りなどCLI側のエラーの場合は `message` を格納する。

行・列は1始まり、列はUTF-8のバイト位置。位置を持たない準備エラーでは0を使う。
